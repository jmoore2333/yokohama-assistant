## Architecture

Workspace crates: `crates/yokohama-core` (library), `crates/yokohama-cli` (game driver), `crates/yokohama-oracle` (independent rules oracle), `crates/yokohama-difftest` (differential harness), `crates/yokohama-bridge` (BGA capture relay), `crates/gen-data` (YAML→Rust generator), and `crates/yokohama-web` (HTTP API — the browser lane, merged to master 2026-09-11) with its browser client in `web/`. **`yokohama-bridge` depends on NO engine crate and never will** — a localhost-only HTTP sink appending what the browser extension in `bridge/extension/` observes to `bridge-captures/<table_id>.ndjson`; it knows no rules and parses no move — translation is `yokohama-cli`'s `import`, deliberately across that boundary so a capture can never be corrupted by a rules bug. The browser half is read-only toward BGA by construction (copies responses the page already received; issues zero requests of its own). CLI public modules: `describe`/`render`/`repl`/`screen`/`session`/`style`/`wizard` + crate-private `input`/`reveal`/`why` (and `bot`/`suggest`), over a thin `main` — `screen` composes the frame and owns `visible_width` (the escape-stripping measurement every width guard uses); `style` owns ALL ANSI knowledge (identity until `init_from_tty`; `NO_COLOR` honored) and the alignment rule: pad from the PLAIN text — escapes add bytes with zero display width.

  - **The four card indexes and the final score** (`crates/yokohama-web/src/outcome.rs`, `web/src/Index.tsx`): `GET …/index/{orders|techs|goals|sites}[?filter=]` serves `screen_model::build_index` over the WIDENED `Repl::index_placements` — widened rather than copied because its doc defends a leak fence (no other seat's hand). **`target` is always `None`**: the terminal can open an index inside a card capture and number its cards, this API has no capture (the grammar refuses the index words precisely so a digit cannot change meaning), so an index here is a read-only view and numbers nothing. The filter is `card_prompt::parse_filter` — **one card-entry grammar in this project, never a second** — and an unparseable term is a 400 carrying the CLI's own refusal. `GET …/result` is the ranked breakdown, **a 409 while the game is still running**, and a NEW route rather than a widening of `ClientState.scores` (which stays the compact in-frame view its three tests already pin). `Placing.won` is a wire field because **a margin of 0 is not a win** — two seats can tie on points and be separated by the engine's own tie-break.
  - **THE LOCKDOWN RULE (M3 close): the lockdown gate fences COMPUTATION, not PROJECTION.** A read-only GET serves a locked session — M2 settled that for `ports`/`labs`/`areas`/`log`, and `ClientState` reports the lockdown as its prompt — so the card indexes and the final score answer. `/suggest` and `/why` REFUSE, because both re-run the bot against the record the driver declared faulty and an authoritative account of a search over a suspect record is what a lockdown exists to stop. Pinned in both directions and mutation-proven; the asymmetry was a review finding, not a design.
  - **The M3 record is `docs/plans/2026-08-31-web-frontend-m3.md`, and its §9 is the six-lens adversarial review** — 42 findings, 36 reproduced, 5 HIGH, alongside 89 claims verified TRUE. **Read §9.3 before trusting a doc comment in this lane:** five of M3's own sentences were false, in the same vocabulary as M2.5's three, and the method that found them is to try the mechanism the sentence promises rather than to re-read the sentence. - Hidden information — READ THE DISTINCTION, it is load-bearing for Phase 3. **In the engine's REPRESENTATION** exactly one thing is hidden player-to-player: each player's starting order (`starting_order` / `starting_order_hidden`; both dealt cards sit in `orders_removed`; reveals via `extract_order_from_deck`). **From a SEATED PLAYER's view that is NOT the whole hidden set** — a bot handed a raw `GameState` is cheating: the state also stores the exact future `order_deck`/`tech_deck` ORDER and the boxed `orders_removed` pile (at 2P the boxing is largest — the unknown is largest exactly where the first strength milestone is). Those fields are correct for replay/self-play; they are not an observation. **Phase 3.0 built the boundary**: `types/view.rs` + `game/observe.rs` (masks the FIVE-member hidden set — the four above plus `GameConfig.setup_seed`) + `game/belief.rs` (`BeliefSampler`, conservation-consistent determinization) + `game/agent.rs`. **A bot takes a `PlayerView`, never a raw `GameState`.** Masking the seed does not fully close the channel — the public board fingerprints the seed (the seed-oracle residual, closed operationally by full-`u64` recorded seeds; map §8).
