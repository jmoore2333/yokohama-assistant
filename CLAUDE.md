## Project

Rust engine, CLI game driver/live tracker, and AI-player stack for the board game **Yokohama** (Hisashi Hayashi, 2016). Priority order: (1) engine-validated move-by-move tracking of live games via CLI, (2) a computer player that provably plays to win, (3) computer vision — deferred.

## Architecture

Workspace crates: `crates/yokohama-core` (library), `crates/yokohama-cli` (game driver), `crates/yokohama-oracle` (independent rules oracle), `crates/yokohama-difftest` (differential harness), `crates/yokohama-bridge` (BGA capture relay), `crates/gen-data` (YAML→Rust generator), `crates/yokohama-web` (the table layer and its HTTP API) with its browser client in `web/`, `crates/yokohama-wasm` (the same layer compiled to WebAssembly, run in a Web Worker), and `crates/yokohama-worker` (the Cloudflare host's module: the same layer compiled to WebAssembly, one instance per Durable Object) under the TypeScript shell `worker/`, its own npm package. **`yokohama-bridge` depends on NO engine crate and never will** — a localhost-only HTTP sink appending what the browser extension in `bridge/extension/` observes to `bridge-captures/<table_id>.ndjson`; it knows no rules and parses no move — translation is `yokohama-cli`'s `import`, deliberately across that boundary so a capture can never be corrupted by a rules bug. The browser half is read-only toward BGA by construction (copies responses the page already received; issues zero requests of its own). CLI public modules: `describe`/`render`/`repl`/`screen`/`session`/`style`/`wizard` + crate-private `input`/`reveal`/`why` (and `bot`/`suggest`), over a thin `main` — `screen` composes the frame and owns `visible_width` (the escape-stripping measurement every width guard uses); `style` owns ALL ANSI knowledge (identity until `init_from_tty`; `NO_COLOR` honored) and the alignment rule: pad from the PLAIN text — escapes add bytes with zero display width.

- `types/` — serde-serializable state. `GameState` is complete-and-resumable and **history-free by design** (cheap to clone for search; move history belongs in an external action log, never in state). `Move`/`AreaAction` in `types/moves.rs`; typed `MoveError` in `types/errors.rs`.
- `game/` — pure functions over state: `get_legal_moves(&GameState, &Rules) -> Vec<Move>`, `apply_move(...) -> Result<GameState, MoveError>` (clones, never mutates). **`apply_move` is the CHECKED boundary** — it rejects any move not in the current legal list; `apply_move_unchecked` is the internal fast path (moves already drawn from the list). **`is_listed_move` (`game/move_legality.rs`) is the single-candidate EXACT membership check, and `replay_strict_with(.., MoveCheck::Predicate)` (`game/record.rs`) the strict replay built on it — the replay an UNTRUSTED record MUST get (an archive upload, a restored backup: `backup::check_pair`, since security S1b), proven to accept exactly what `replay_strict` accepts by `tests/replay_check_equivalence.rs` (R-SEC2, 2026-10-08); `replay_strict` itself is unedited, and a direct `is_move_legal` replay is never the answer, since that predicate is wider on a president move's witness path.** `Rules::standard()` from generated registries; `Rules::empty_for_tests()` for fixtures; `Rules::content_hash()` stamps `GameRecord.rules_hash` (`replay` warns on mismatch; `replay_strict` adds per-event invariant checks — the training-record path — and verifies the terminal digest). Seeded `new_game(...) -> PendingSetup` + `finalize_setup`; decks live IN `GameState` (`order_deck`/`tech_deck`, last = top; `orders_removed` for conservation); `place_setup_dummies` is `pub` (Phase-3 primitive for a valid 2P state outside `new_game`).
- `game/search_actions.rs` — the FACTORED bot-facing action source, families-first: `families()` names the legal families; `family_len`/`iter_family`/`sample_family` page or sample WITHIN one (`sample_family -> Option<Move>`: `None` on a structurally-empty family — `families()` deliberately emits the tag without probing emptiness). **THE THREE FAMILY-COST SHAPES DIFFER — never transfer one family's language to another:** *retreat* LAZY serve-one (mixed-radix index; `family_len` exact closed form); *placement* LAZY generate-and-filter (`family_len` an honest UPPER bound — `iter_family` is the authority on realized moves); *routes* COMPUTE-PER-CALL, small but exact, no cache — a caller needing count AND moves pages the iterator rather than asking twice (L10). Small families delegate to the exhaustive generators — equivalent by construction. **`get_legal_moves` stays the authority**; these modules are purely additive and are what search calls.
- `game/route_enum.rs` — the exact allocation-free President-route enumerator: reproduces the frozen `enumerate_president_routes` EXACTLY (same pairs, order, lex-least witness); `movement_routes_family` assembles the WHOLE Movement family as `legal_moves.rs` does. The win is allocation shape, not complexity (the label is three scalars, so the DFS carries `(u8, u32)` over fixed arrays; worst-case TIME is still `O(affordable simple paths)`). Totality is a PRE-FLIGHT probe — `fits_fixed_arrays` checks all bounds BEFORE any write; a failing state (hand-built fixtures only) delegates to the frozen path, never panics. The routes family is SMALL — **max OBSERVED 694 adversarial / 66 organic under the shipped policy (policy-conditional, L11), NO label ceiling known (L9): cite "max observed under harness X", never a bound.**
- `game/move_legality.rs` — single-candidate legality for a search that PROPOSES a move: `is_move_legal(state, mv, rules, mode)` (exhaustive match, no `_` arm — a new variant is a compile error, not a silent rejection) + `is_president_path_legal`, and `is_listed_move(state, mv, rules)` — EXACT membership in the legal list for one candidate: `is_move_legal(.., Canonical)` AND the Movement family's own list for `MovePresident`/`PlacePresident`, `is_move_legal(.., Canonical)` alone for every other variant (the check `replay_strict_with(.., Predicate)` folds with). Re-stated cheap per-arm predicates (design A, won by measurement; apply-probing is far slower AND unsound alone — raw arms defend only structure and never read `turn_phase`). `PathMode::RulesLegal` accepts any rules-legal WITNESS — deliberately WIDER than list membership with ZERO new labels, so **equivalence tests compare `MovePresident` by `(destination, RouteVector)` LABEL, never raw path**; `PathMode::Canonical` adds only the generator's teleport suppression and does NOT verify lex-least witness selection. ZERO narrowings vs `get_legal_moves` since rev 4: the Canal exclusion is single-sourced in the two shared movement predicates (`is_possible_action_area_full`, `can_step_onto`) so generator, predicates, both route searches, and apply agree BY CONSTRUCTION (pinned by `the_canal_is_excluded_by_construction_across_generator_predicate_and_apply`).
- **3.2 — the arena and the policy rungs** (`game/seeds.rs`, `game/metrics.rs`, `game/policy.rs`, `game/arena.rs`, + `DecisionHandle`/`FamilySize`). `RolloutPolicy` = the three preserved rungs: `Uniform`, `RetreatAverse` (never volunteer a retreat), `FamilyWeighted { retreat_ppm, recovery_min_of }` (defaults 166,667 ppm, k=5; FULL SUPPORT at every recovery vector — the defect it fixes). **Sampler-side ONLY: the engine's legal list is never weighted.** Lives in core so the fuzzer reaches it. `DecisionHandle` = the enumerate-once handle (L10 as a property of a type); its DFS-counter pin is **harness-scoped, never globally armed** (the CLI bot path legitimately pays 2 in debug) and **structurally blind at in-hand Movement points** — hence the separate per-edit pick allocation bound with its own in-hand cell. `FamilySize::{Exact, UpperBound}` keeps placement's upper bound from being silently summed into exact sizes. The arena defines its OWN `ArenaAgent` seam (not `HonestAgent`, whose `choose_move` takes a materialized `&[Move]` — the ceiling the driver exists to avoid); honest by construction (`observe` → `BeliefSampler` K=1 → `DecisionHandle` → `pick` → `is_move_legal` → `apply_move_unchecked`); sampler failure is a **typed hard error with NO fallback arm** (`TrivialHonestAgent` silently falls back to the TRUE legal list — an arena inheriting that would emit privileged-play games into the corpus). **Seeds are type-enforced**: the public surface takes `WorldSeed`, never bare `u64`; masters from OS entropy per evaluation run, recorded; `SeedSchedule::diagnostic(master)` is the reproduction path and its NAME is the waiver; **no value-based seed checks anywhere** — the enforced property is the DERIVATION. `GameRecord.run` carries `RunProvenance`/`SeatProvenance` (replay-inert); corpus layout `rev<N>/<players>P-<cell>/<seed:016x>-<arr>.json`.

## Conventions

- TDD: failing test first. The repo's commit history is strictly TDD — keep it that way. Suite green + zero warnings after every task.
- Design docs and implementation plans are dated files in `docs/plans/` (`YYYY-MM-DD-topic.md`). Workflow: brainstorm → spec → implementation plan → execute. Dated artifacts are frozen phase records — never edited after their phase closes; corrections are recorded forward.
- Strong typing at boundaries: IDs have `try_new`/`TryFrom` for external input; bare `new` is for internal logic only.
- **Every INVISIBLE non-ASCII code point in code is a `\u` escape; a visible glyph may be raw** (M6.5c2): a no-break space, an ideographic space, a zero-width joiner or a Kelvin sign in a cell is written as its escape, so what a test asserts is readable and a grep for invisible code points over the tree reads nothing.
- Update `guidingpath.md` at phase transitions and for new design decisions; never claim a phase complete unless its executable gate passes. The decision log is append-only (rows are never edited; the archived rows live verbatim in the three append-closed archives the Project section above names).
- The tester-facing guide pair `docs/cli-guide.md` + `docs/cli-guide.html` is the AUTHORITATIVE CLI documentation: any change to `yokohama-cli` behavior or user-visible text updates BOTH formats in the same commit (word-identical modulo markup; ⚠ in the `.md` == the `DIFFERS` badge in the `.html`). The `guide_sync` test enforces the mechanical slice — HELP_TEXT command coverage, the move grammars, the computed board widths, byte-identical §5 command blocks.
- **CLAUDE.md holds standing rules only (owner-directed; consolidated 2026-08-19, 2026-09-23 and 2026-10-04 — the first two relocation maps are `docs/plans/2026-08-19-docs-consolidation.md` and `docs/plans/2026-09-23-claude-md-consolidation.md`; the third pass is guidingpath's 2026-10-04 row).** Every session and every subagent pays for this whole file before reading a line of its task, so it carries no status narrative, no counts or walls and no history: status lives on the board (`docs/handover.md`) and in guidingpath's Current state, counts and walls in each close, and the narrative, the measurements, the review findings and the story behind each lesson in the close document, which is the record of record. At a close: record the readings in the close, update the board, and state a genuinely new standing rule, fence or trap here in a sentence or two. The test: a sentence that says how something came to be belongs in the close; a sentence that changes what the next agent does belongs here.
- **Lessons this project paid for** — one line each; the story is in the named record:
  - Pin a refusal ORDER with two-defect probes at adjacent links — a single-defect probe pins nothing about order (M6.2).
  - Try the mechanism a sentence promises rather than re-reading the sentence: cycle after cycle, the top review yield is a false sentence a milestone wrote about itself (M3 record §9.3; every close's §7).
  - A cell on the wrong host is not coverage — the catcher is the cell whose mechanism the assertion actually runs through (M6.4).
  - A regenerated fixture corpus freezes a leak as faithfully as a fix — read the diff (M6.1).
  - A literal-name check misses a field re-added under a DIFFERENT name — pin by value and by key set (the 2026-09-06 owner corrections, §5).
  - A reviewer's mutants run on an EXPORT (`git archive`), never in a tree an implementer holds — two agents in one tree lose each other's edits (M6.5c close §4).
  - An acceptance reply that asks for changes after a DONE IS a fix-round dispatch: say "as a new commit" in it, and sequence it (M6.5c close §4).
  - A read that never settles is a state, not a delay: a wait for a fact needs a bound (M6.5c, I-86).
  - "The same code" is a premise a stored replay must CHECK, not assume: stamp what gives a line its meaning — the engine's order included (M6.5c, I-85, I-91).
  - A plan's code block is the single source: correct it THERE first and transcribe byte for byte, and have the implementer PROBE the brief's code before reporting — every task of the security core PR came back with a real gap that way, and the plan and the code never diverged (the core PR's Review record, R-10–R-18).
  - A permit or a lock taken in an async handler's frame is released when the client hangs up while the blocking work runs on — hold it inside the work — and a count-then-write is a race until a lock says otherwise (security S1b Tasks 3–4; both measured, one over real TCP).
  - A fix report's "equivalent mutant" is a claim, and a backstop that "bounds by construction" has as many holes as there are literal constructions: the re-reviewer's one run read ML green where the implementer had reasoned it could not fail, and a side note counted twenty-two struct literals the cap never saw (S1c Task 1).
  - A fix that rewrites each of several caller values inside one sentence needs a mutant PER VALUE CLASS: the two route cells caught the controller's raw copy and let the parameter key's loop be dropped unseen, until the re-review's extra mutant ran it green across 492 cells (S1 stack review, re-review Finding 1).
