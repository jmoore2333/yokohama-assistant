## Architecture

Workspace crates: `crates/yokohama-core` (library), `crates/yokohama-cli` (game driver), `crates/yokohama-oracle` (independent rules oracle), `crates/yokohama-difftest` (differential harness), `crates/yokohama-bridge` (BGA capture relay), `crates/gen-data` (YAML→Rust generator), `crates/yokohama-web` (the table layer and its HTTP API — the browser lane, merged to master 2026-09-11) with its browser client in `web/`, `crates/yokohama-wasm` (the browser host: the same layer compiled to WebAssembly and run in a Web Worker — M6.5b), and `crates/yokohama-worker` (the Cloudflare host's module: the same layer compiled to WebAssembly, one instance per Durable Object — M6.5c) under the TypeScript shell `worker/`, its own npm package. **`yokohama-bridge` depends on NO engine crate and never will** — a localhost-only HTTP sink appending what the browser extension in `bridge/extension/` observes to `bridge-captures/<table_id>.ndjson`; it knows no rules and parses no move — translation is `yokohama-cli`'s `import`, deliberately across that boundary so a capture can never be corrupted by a rules bug. Small families delegate to the exhaustive generators — equivalent by construction. **`get_legal_moves` stays the authority**; these modules are purely additive and are what search calls.

  - **Identity** (`identity.rs`): `YOKOHAMA_WEB_IDENTITY` = `open` | `cf-access` | `worker`, with **NO default — an unset variable exits 1**, because a server that guesses its own door is a server whose door nobody wrote down. Each mode reads exactly ONE header and no other (`X-Yokohama-Claimed-User` / `Cf-Access-Authenticated-User-Email` / `X-Yokohama-User`), so a forged header for another mode changes nothing; `User::parse` trims and lowercases ONCE, so a seat is the same seat on the next request; under `worker` the literal `anonymous` counts as ABSENT, which is what makes an unprotected Worker fail CLOSED. **`open` is the self-host door and also the dev door, not a security boundary** (anyone who can reach the server may use any name), and it is the `open-door` cargo feature: a public build (`--no-default-features --features server`) REFUSES `YOKOHAMA_WEB_IDENTITY=open` by name. Every payload the server builds is built for the caller.
  - **The store** takes a typed `Doc` on every call — `Record`, `Table` (`<id>.table.json`), `Chat` (`<id>.chat.json`) and `House` (`_house.chat.json`; `is_safe_id` refuses a leading underscore, so the underscore IS the reservation) — with `write_if_version` and a typed `Conflict`/`Io`. The kinds share one directory, so `is_safe_id` refuses any id ending in a `RESERVED_ID_SUFFIXES` entry (`.table`, `.chat`; case-insensitively, because APFS and NTFS fold case), and **a new document kind needs a new reservation** — the derivation assert compares the two lists' LENGTHS before it zips, so it says so. `check_house_id` is one helper called from `FsStore::path` and from both `MemStore` entry points.
  - **The table document** (`table.rs`) is who may sit here: seats `Human { user, name }` | `Bot` | `Open` (`user` is the key and `name` only a label), the keeps, the setup `seed` (which lives here and NOWHERE on the wire), a `status` of `Open` | `Dealing` | `Playing`, an optional `Lock { salt, hash }` (16 OS-entropy bytes and SHA-256(salt ‖ password), compared by a fold of XORs), the `unlocked` roster of watchers who gave the password (capped, never on the wire), and a `TurnMirror` of `to_move`/`over`/`winner` — **a cache** that `persist` refreshes, whose conflict is IGNORED, and which exists so the lobby is built from table documents rather than rebuilt sessions. **"over" is NOT a status**: it is read from the session, because a stored copy goes stale. `TABLE_SCHEMA` is **3** and every earlier binary refuses a schema-3 table, so **rolling back across M6.5a is a SCHEMA rollback** (RUNBOOK §5). **Every field read out of a stored document is an INPUT**: `check_shape` bounds each one (`players`, `start_seat`, every `keeps[i]`, `to_move`, the lock) because it runs under the table's lock, where a `PlayerId::new` panic poisons the mutex and takes the whole process out. `games.rs` is the record lifecycle and `tables.rs` the table lifecycle: `join`/`keep`/`settle`/`finalize`/`flip_to_playing`/`delete` hold the TABLE's own `lock_for(id)` and `create` alone the global `table_lock` (a drawn id is not yet one table), which is why `delete` tombstones BEFORE it unlinks.
  - **Seats, the deal, and who may read.** A create answers 201 at `open` (a seat still open) or `dealing`, and the join that fills the last seat flips the table to `dealing` in the same write. Each seat reads only its OWN two cards from `…/deal` — another seat's deal never reaches the wire (`DealView.cards` is the caller's own, and null together with `seat` while they wait; no payload carries another seat's cards or keep) — and **the technologies and goals are withheld until the choice** (`withhold_until_the_choice`: a VIEW, not a rule, because the owner's edition takes the secret choice before they are dealt; the seed, the draw order and `SEMANTICS_REV` are untouched). A caller keeps only for a seat they hold — the seat is checked BEFORE the status, so a stranger's keep is a 403 at every status and learns nothing — and the LAST human keep finalizes record-first. **`admitted(state, id, user) -> (TableDoc, Viewer)`** is every route's door: a seat holder at any status; ANY signed-in caller at an `open` table, for `table`, `events` and `stream` only; nobody without a seat at `dealing` (nobody watches a deal); a `Spectator` at `playing` or over once the table has no lock or their email is on `unlocked` (`POST …/{id}/unlock`); and a locked table's reads refused with "this table is locked — unlock it first". **`viewer_seat`** is the acting seat when the caller holds it, else the caller's lowest, so `…/at/{k}` is the caller's own seat at every `k`; masking is `SeatFacts`' — the CLI's own mechanism, widened by `Repl::index_placements_for`, never re-implemented here.
  - **Spectators, the acting seat, and undo.** A spectator's projection is a NON-ACTING seat's frame: `facts_for(Spectator)` hides every hand, and the projection DROPS the `Hand` panel (`seat: null` on the wire), because a hidden hand still yields a panel that would single out one seat as "yours". **A spectator writes nothing but chat**, and the write sweep proves it behind a store that PANICS on any record read, so "refused before the handle is touched" is a crash and not a sentence. **The acting-seat fence on `input` NEVER drops for a non-acting caller at ANY status** — at game over and lockdown only the 403's wording changes. **Undo** (R-P6): at a table with ONE distinct human email it is the CLI's undo; otherwise only while the trailing event's mover is the caller's seat AND `current_player` still is (replay-derived from `record::state_at(record, len-1)`, checked BEFORE the fence so the answer is always in R-P6's words), and at a FINISHED shared game **nobody undoes**.
  - **The ONE mutation is `POST /api/games/{id}/input` over `Repl::step`** — `step` IS the state machine and a second dispatcher would fork the option numbering — **fenced by `grammar::is_gameplay_line`, an ALLOWLIST**: `step` is the TERMINAL's front door and also answers `save <path>` (an arbitrary filesystem write) and the sticky overlay words (`?`/`index`/`orders`/`techs`/`goals`/`sitecards`/`view`) after which a NUMBER selects a card rather than a move. TWO rules, not one: a HEAD may only be a listed word or a number/area, because `save` and `view` are ordinary alphanumeric words a single permissive rule lets through. What those words reached are read-only GETs instead: `…/ports`, `…/labs`, `…/areas`, `…/log`.
  - **NO play payload carries the setup seed** — hidden-set member #1 (`game/observe.rs`), which regenerates both decks, the boxed pile, the board and every deal. `TitleModel::seed` is `Option<u64>` (the CLI passes `Some`, this crate `None`), `ClientState` has no seed field at all, and default game ids keep the `sim-{…:016x}` shape but draw INDEPENDENTLY of the seed. Two fences that are deliberately NOT the same check: the server searches the committed corpus for the VALUE (the pin above, whose anti-vacuity partner asserts the seed IS in the stored table document and NOT in the create's reply), and the client asserts the SHAPE (`web/src/wire/contract.test.ts`). The one place the value crosses the wire is INBOUND, in `POST /api/games`, where `WireSeed` serializes as a STRING: a `u64` through a JS number rounds silently past 2^53 and deals a different game.
  - **Persistence: nothing exists only in memory, with three named exceptions.** Every applied move the server acknowledged is persisted as its `GameRecord`, and an absent handle is rebuilt through `Session::from_record`. What does not survive a rebuild: `Repl::sub` (an open multi-step picker — `Input::expect` exists for exactly that case), `Repl::privacy`, and any move whose WRITE failed, which is why the reply carries `APPLIED BUT NOT SAVED` out loud instead of reporting a refusal the server did not make. `Games::persist` stamps the terminal digest through `Session::to_record_json` (serializing `record()` directly would disarm the engine's own provenance refusal), compares record identity by seed FIRST (a name is not a game), and then **COMPARE-AND-SWAPS against a digest of the exact JSON this process last wrote or read**, holding the lock across the read, the compare and the write — an undo POPS events, which a length test cannot tell from a stale handle. It DETECTS a cross-process conflict and does not PREVENT one; where this process has no base it falls back to the length test. A CONFLICTING write EVICTS the handle so a stale `Repl` cannot go on answering 200; an I/O failure does not; `create` holds its own lock across check-then-write.
  - **Transport** (`signal.rs`): `Signals` holds one `tokio::sync::watch` channel per table and one for the house, bumped only in success arms, and **a bump follows its write and never precedes it** — proven by gated cells that park the real write and read the receiver quiet. `GET …/{id}/stream` is server-sent events: the current `Events` on connect, one `event: signal` frame per bump, `event: end` on a delete, a comment heartbeat every 25 s (under the edge's 100 s), no `id:` or `retry:` line, and no game lock held across an await; a 403 or 404 ends the stream and any other error writes a comment the client drops. `GET /api/stream` is the house channel, `{seq, chat}` and silent on connect, so the lobby refetches on any frame. `SIGNAL_KIND` is `"sse"` on the NAS, MEASURED through the tunnel both ways (M6.3 close §2.1), with the held-request arm dark; on the Worker it is `"ws"` — a hibernatable WebSocket carrying the SSE frames' data as `{"event","data"}`, one frame per socket per reply, each computed for that socket's own viewer, with `ping → pong` answered at the edge without waking the object. **The client reads the stream with `fetch`, not `EventSource`** (which cannot carry this server's identity header; `web/src/sse.ts` is the line parser), `usePolled` arms NO timer while connected on the stream arm — the socket arm's one timer is its 30 s keep-alive, which stops at hang-up and sends only while the socket is OPEN; after a close it did not make, the socket arm probes ONCE through the source's own `once()`; and no stream or socket opens before the deployment's transport is known (a wait bounded by `BOUND_MS`, M6.5c's I-86) — a browser holds ONE stream per VISIBLE tab and none in a background tab (R-P8), and a game screen holds its stream at every status of the game while visible — `send` parks any frame that lands while it posts, so a self-bump is never walked as an opponent's move. **A consumer's `active` must not toggle on its own handler**: that is a poll's reason, and on a held connection it reopened the stream once per applied move.
  - **The Worker host (M6.5c) — the standing rules.** **The strings rule**: the shell never `JSON.parse`s a record or a table document (a seed is a `u64` a JavaScript number rounds past 2^53) — its only parses are the house copy (seed zeroed), an `events` reading, its own `meta` JSON and an archive plan — and Rust-made fixtures reach the pool as text. **Two time bases**: every time the shell keeps (`written_at`, alarm deadlines, retry dues, the marker's `at`, a generation's `at`) is `Date.now()` in milliseconds; the module's pinned reading, in whole seconds, feeds only what the layer stamps. **One batch per request**: a request's read, dispatch and write contain no `await`, every write and the alarm it makes due go in ONE `transactionSync` batch with `setAlarm` beside it, and frames, the house push and the R2 upload follow. **`X-Yokohama-*` is stripped**: the Worker removes every client header named `x-yokohama-…` and sets `X-Yokohama-User` only from a verified Access assertion, judged on the RAW claim (outside tab, space and visible ASCII it is no one) and lowercased by ASCII only; a foreign `Origin` on a WebSocket upgrade is refused. **The dev door** (`YOKOHAMA_DEV_DOOR=on`: the `yokohama-worker` Service Auth credential plus `X-Yokohama-Claimed-User`) is this host's `claimed` — it can claim any identity that is an address by `User::parse`'s rule, never an operator's rights — and it goes off with the public door. **`YOKOHAMA_WEB_ADMINS` is a Worker SECRET** (`wrangler secret put`, from stdin), never a `vars` entry, and no document spells its value. **The deploy guard** (`worker/scripts/deploy-guard.mjs`, run by `npm run deploy`) refuses a debug or unoptimized module, an assets tree that is not the release, a `workers.dev` or preview URL, the test clock, any drift in the `assets` block, object bindings, migrations or bucket between the two wrangler configurations, an operator list in `vars`, and a STALE build — a `gen/` whose source stamp no longer matches, or an assets tree assembled from an earlier `web/dist` or `worker/static`. **`wrangler tail --format json` is pretty-printed JSON**: parse it by whole objects, never by lines. **An exception escaping an object** is a host-written 500 `the server could not answer — try again` with an `object-failed` line. **A picker row carries the code's digest** (the engine's, the CLI's and the layer's sources), so a deploy that changes any of them drops open pickers rather than re-feed them, logged `picker-dropped`. **A generation's time is milliseconds**, so a rollback to a version that drew seconds (the eighteenth deployment or earlier) is a GENERATION-ORDER rollback — a re-created table goes unlisted until its retired generation is pruned (`worker/RUNBOOK.md` §6). **A first visit reads "connecting…"** on both hosts until its first connection: the client waits (bounded by `BOUND_MS`) for the deployment's transport before it opens a stream or a socket.
  - **Chat** (`chat.rs`): a `ChatDoc` of `Message`s with a TAGGED author (`seat` | `watcher` | `bot`, the last produced by no route yet). `trim` drops from the OLDEST end and never reuses a number, `check_shape` runs on read AND on write, and **length is never a refusal in either direction** — an over-cap text is served as stored and an over-keep document trimmed on its next append, so lowering either limit on a running volume takes no table out. One appender behind two seams (a table's own lock then `bump_table`; the house's `house_lock` then `bump_house_chat`), **keyed by the key it READ, never the stored `id`**. **Delivery is a COUNT, never the text**: `Events` carries `chat` and the house frame is `{seq, chat}` — a `watch` channel can lose one of two values between reads, so a frame carrying text could not survive the seam. A seated caller is named by their SEAT (a name in the body is a 400); a watcher may send one, and **a watcher's post is the one write a spectator may make** — POST ≡ GET at every admission cell, so a locked table's chat is behind its password both ways. Three launch variables WITH defaults — `YOKOHAMA_WEB_LOBBY_CHAT` (on), `YOKOHAMA_WEB_CHAT_KEEP` (500, or `all`) and `YOKOHAMA_WEB_CHAT_TEXT` (500) — are reported on `/api/health` so the client sizes its input from the server's rule, and a BAD value still exits 1 naming the variable.
  - **Deployment switches and the archive** (M6.5a, M6.5b2). `YOKOHAMA_WEB_MULTIPLAYER=off` takes the game and chat rows out of the route table and the three stream routes off the axum router, so there is nothing to probe; `/enter` is a 302 turnstile served when EITHER multiplayer or the archive is on, which is how Access moved off the hostname without the app ever learning that Access exists. **The archive** (`YOKOHAMA_WEB_ARCHIVE_DIR`; `/api/health`'s `archive` reads `off` or `dir`): a finished game is archived ONCE under `rev7/over/` and an abandoned one under `rev7/abandoned/` — a failed put at game over is logged and leaves `archived_at` unset, a failed put at abandon REFUSES the delete. `GET …/{id}/record` serves a seat holder's FINISHED game as the store's exact bytes (409 while it runs, 403 for a watcher). `POST /api/archive` strict-replays what a browser sends and files it under `browser/<caller_segment>/` by the leaf the replay shows; `backup.rs` is ONE validator (`check_pair`) that route and the backup envelope both call, so the two cannot drift.
  - **Single-player runs entirely in the browser** (M6.5b, M6.5b2). `web/src/local/` runs the layer in the Web Worker as ONE serialised actor with an ownership generation checked in every write; every move is committed to IndexedDB BEFORE the page is answered, and an unreadable store is a refusal, not a trap; the app asks to keep its storage at the FIRST COMMITTED MOVE, never at boot; two tabs on one game settle through the Web Locks API; an export takes one whole pair, from the Worker only where that tab OWNS the game at the current generation; and the client's local arm is chosen by the `local-` id prefix or the caller's intent. Every host serves the batch run route `GET …/at?from=&to=` the walk uses. The first screen (`#/`) is a door that asks the server for NOTHING. **The release is precached whole** under a name that is a digest of its own bytes (`web/src/sw.ts` is the service worker's SOURCE; the precache generator bundles it into `dist/sw.js` with the inventory and the cache name built in): installed all-or-nothing with every body digested, the update offer rendered on the door alone and taken by a click, a waiting release that nobody clicks activating by itself once every old page has closed, the previously ACTIVATED generation RETAINED (a tab that did not click is served its own release from it), and `/cdn-cgi` never intercepted, because the Access login hop lives there. A game finished offline is queued with its reason and uploaded when the connection returns, and Abandon has THREE answers — send, delete, or ask — because "unknown" is not "off". A restore never erases: identical bytes read "already on this device", a clash REFUSES by name, and a save at another `SEMANTICS_REV` is kept and listed under "Will not open here" with a two-click Remove. The fonts and help pictures are self-hosted, so an offline launch keeps its typefaces.
  - **The explanation surface** (`explain.rs`, `web/src/Explain.tsx`): `GET …/suggest` and `GET …/why[?event=n]` are the only two routes that COMPUTE — they read an opinion about a state, never advance one, and DROP the per-game lock before searching. **A typed refusal is a 200 with a refusal body**, not a 4xx: `why` declining because the last move was a human's is the answer. The DTOs mirror `eval::explain` without touching core; the counters are `driven_runner::counter_rows`' fifteen named verbatim; every move is worded by `describe_move`; `why`'s twelve refusals are `why::account_parts`' own strings carried VERBATIM — **that gate is reached, never reimplemented**. `suggest`'s four refusals are the one place the layer words anything itself (`SuggestRefusal::message`'s doc rules on each: `GameOver` byte-identical to the CLI's line, `LiveMode` hand-wrapped, `BotSeat` and `Locked` AUTHORED). **The exact-sum identity `total == Σ product + terminal.value` rides the payload** and the client foots it on screen; all 34 terms ship, the zero ones included, for the READER — a term shown at zero is one that was computed. **`ranking[].chosen` is a wire field, not `index == 0`**: ties at the top are broken by a keyed draw. **`why` masks the roads not taken** under `HandVisibility::Masked` (an unplayed `FulfillOrder` words as "Fulfill an order from hand"); the move PLAYED is never masked, and `suggest` masks nothing.

Pinned in both directions.

## Conventions

- TDD: failing test first. The repo's commit history is strictly TDD — keep it that way. Suite green + zero warnings after every task.
- Design docs and implementation plans are dated files in `docs/plans/` (`YYYY-MM-DD-topic.md`). Workflow: brainstorm → spec → implementation plan → execute. Dated artifacts are frozen phase records — never edited after their phase closes; corrections are recorded forward.
- Strong typing at boundaries: IDs have `try_new`/`TryFrom` for external input; bare `new` is for internal logic only.
- **Every INVISIBLE non-ASCII code point in code is a `\u` escape; a visible glyph may be raw** (M6.5c2): a no-break space, an ideographic space, a zero-width joiner or a Kelvin sign in a cell is written as its escape, so what a test asserts is readable and a grep for invisible code points over the tree reads nothing.
- Update `guidingpath.md` at phase transitions and for new design decisions; never claim a phase complete unless its executable gate passes. The decision log is append-only (rows are never edited; pre-3.5c rows live verbatim in `guidingpath-archive.md`, append-closed).
- The tester-facing guide pair `docs/cli-guide.md` + `docs/cli-guide.html` is the AUTHORITATIVE CLI documentation: any change to `yokohama-cli` behavior or user-visible text updates BOTH formats in the same commit (word-identical modulo markup; ⚠ in the `.md` == the `DIFFERS` badge in the `.html`). The `guide_sync` test enforces the mechanical slice — HELP_TEXT command coverage, the move grammars, the computed board widths, byte-identical §5 command blocks.
- **CLAUDE.md is current-state only (owner-directed; consolidated 2026-08-19 and again 2026-09-23 — the relocation maps are `docs/plans/2026-08-19-docs-consolidation.md` and `docs/plans/2026-09-23-claude-md-consolidation.md`).** Every session and every subagent pays for this whole file before reading a line of its task, and between those two passes it regrew 3.8× by accretion. So at a cycle's or phase's close: update each count IN PLACE, naming its reading (the commit or close it was taken at), with no lineage; add ONE row to the web lane's records table (or point at the phase's close); state a genuinely new standing rule, fence or trap in a sentence or two; and put the narrative, the measurements, the review findings and the story behind each lesson in the close document, which is the record of record. The test: a sentence that says how something came to be belongs in the close; a sentence that changes what the next agent does belongs here.
- **Lessons this project paid for** — one line each; the story is in the named record:
  - Pin a refusal ORDER with two-defect probes at adjacent links — a single-defect probe pins nothing about order (M6.2).
  - Try the mechanism a sentence promises rather than re-reading the sentence: cycle after cycle, the top review yield is a false sentence a milestone wrote about itself (M3 record §9.3; every close's §7).
  - A cell on the wrong host is not coverage — the catcher is the cell whose mechanism the assertion actually runs through (M6.4).
  - A regenerated fixture corpus freezes a leak as faithfully as a fix — read the diff (M6.1).
  - A literal-name check misses a field re-added under a DIFFERENT name — pin by value and by key set (the 2026-09-06 owner corrections, §5).
  - Headless is not headed: headless Chromium never asks for `favicon.ico`, so four headless reviews reported "zero console errors" over a 404 on every screen (M6.4 close §4.5).
  - A reviewer's mutants run on an EXPORT (`git archive`), never in a tree an implementer holds — two agents in one tree lose each other's edits (M6.5c close §4).
  - An acceptance reply that asks for changes after a DONE IS a fix-round dispatch: say "as a new commit" in it, and sequence it — M6.5c broke the rule twice, once by its own author (M6.5c close §4).
  - A route-based header injection never reaches a page-opened WebSocket upgrade; only context headers do — and a thrown Playwright API call prints its request headers, the cookie included, to the reporter and onto disk: wrap every live call, and turn tracing off (M6.5c, I-75, I-79).
  - A read that never settles is a state, not a delay: a wait for a fact needs a bound, or the screen says "live" over nothing — and a transport fix is reviewed on BOTH hosts (M6.5c, I-86).
  - "The same code" is a premise a stored replay must CHECK, not assume: stamp what gives a line its meaning — the engine's order included (M6.5c, I-85, I-91).
  - A covered headed window reads HIDDEN on macOS whatever Chromium's occlusion switches say, and Chromium widens a window to 500 px at least: lay a headed run's windows out from bounds READ BACK, and make visibility a precondition the spec asserts (M6.5c close §3.3).
