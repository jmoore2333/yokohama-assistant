# Phase 3.5a — CLI redesign: implementation plan

**Date:** 2026-08-05 · **Executes:** `2026-08-05-phase3.5a-cli-redesign-spec.md` (§0 rulings binding; the approved mocks are the design authority) · **Branch:** `phase3.5a-cli-redesign`.

## Execution protocol

Per task: **one fresh Opus implementer** (brief carries task id + expected HEAD as literals — L27; abort on HEAD mismatch; ONE commit; never amend after DONE) → **one independent Opus reviewer** (clean eyes; scratch harnesses where cheap; findings MUST/SHOULD/NOTE) → the orchestrator verifies via git, adjudicates, applies fixes in its own commit, dispatches the next task at the new HEAD. TDD: the failing test lands in the same commit as the code that greens it. After EVERY task: `cargo test -p yokohama-cli` + `cargo clippy --workspace --all-targets -- -D warnings` (exit codes checked unpiped — L17); `guide_sync` green on any commit touching user-visible text; `cargo test -p yokohama-core` re-run at wave boundaries (no core edits are planned — a core diff is a STOP). L28 (WIP capture commits make owner pauses free) and L31 (per-task stuck alarms) stand. **Owner visibility:** each surface-landing task ends with a committed `cat`-able capture and/or a Forge render the owner can eyeball — cheap course-correction is the point.

**Cutover strategy (keeps the CLI playable after every task):** the redesign swaps the composed frame INCREMENTALLY — each surface task replaces its region of the live frame and re-points that region's lib tests in the same commit. The piped line protocol is untouched throughout; the per-edit dogfood slice must pass after every task, `piped_dogfood` (release) at the wave boundaries.

Tests: model builders over fixture states (no terminal); the reusable `assert_exact_width` helper and its first use. No rendering change yet. *Watch: no ANSI, no `style` import in this module — reviewer checks the import list.*

**T3 — dashboard panels.** Players (goods, assistant zones, building zones, per-tech summary lines, mercenaries unused/used, president, orders), tracks summary (rewards ranges, dummy, customs in IMPORTS), achievements by category, hand-as-card; 2P side arrangement cut over. **T4 — decision zone.** Phase chain with current-phase lit; "YOU ARE DECIDING" line per decision kind (worded via `describe`); numbered options in words with fees/steps; **dimmed not-offered rows** (from the engine list's complement with engine-derived reasons — Movement first, extendable); **◈ marks** fed to T2 from the current legal list during Movement. Bare-Enter forced-option ceremony preserved. *Watch: the deciding-line copy for every `PendingChoice` variant — exhaustive match, no `_` arm.*

**T5 — the `CardPrompt` helper + the ORDER index.** One input helper implementing §0.2/§0.6: menu numbers, bare-id, name/prefix, `?` opens the index, echo-back before commit, duplicate refusals with location, running already-placed line. **T7 — wizard redesign.** All entry through `CardPrompt`/indexes; tile offers filtered by remaining-legal with live counts (F2); achievements one-per-category at parse time (F1 — wizard-side only; if the implementer believes a reconcile-side check is warranted, STOP and flag the owner, do not land it); deals/ports/labs via index with echo-back; orientation skeleton + board check preserved; review/edit flow re-pointed. *Watch: the sim tail (keep scores, bot seats) restyled but semantics identical; wizard tests are the biggest re-point block — budget for it.*

**T8 — reveal flows.** Reveal prompts through `CardPrompt` (index available mid-reveal); atomic move+reveal commit, echo, `log` audit, desync lockdown all byte-equivalent in semantics; `reveal <seat>` grammar kept as alias with a menu path added. *Watch: NO new record event kinds; the reveal choreography tests re-point but their assertions about ORDER and atomicity stay verbatim.*

**T9 — readline layer + toggles.** TTY input via the line editor (↑ history, editing); piped stdin bypass with byte-identical protocol (dogfood proves it); single-keypress view toggles if key bindings are cheap, else single-letter + Enter recorded as the shipped minimum. Dependency license named in the commit and PR. *Watch: the editor must not intercept piped mode or tests — construction gated on TTY detection like `style::init_from_tty`.*

**T10 — 3P/4P arrangements.** Below-dashboard layouts per the 4P mock (player columns, compressed track/achievement lines); per-count constants; the 4P frame's own width sweep. *Watch: 3P is the untested middle child — its own fixture.*

**T11 — remaining views + the guide pair.** `ports`/`labs`/`goals`/`hand`/`log` restyled to the pattern; the `view` menu updated; then the FULL rewrite of `docs/cli-guide.md` + `.html` (word-identical modulo markup) — new screens, new grammar, new indexes, the ⚠/DIFFERS conventions kept; `guide_sync` re-pointed. *Watch: the guide is tester-facing law — screenshots/captures regenerate from the shipped binary, not from mocks.*

**T12 — sweep + Forge pass + polish.** Full lib-test re-point audit (no stale expectations); `piped_dogfood` release green; the Forge visual pass — every surface driven in a real PTY at ≥ the floor and compared against its approved mock, captures committed; polish waves from the orchestrator's own play-through. Then the close sequence (spec §6): six-lens review → fix waves → **the owner's live gate game on the new surface** → disposition + 3.5b handover → merge.

## Sequencing and sizing

Linear T0→T12; T5/T6 may overlap T3/T4 if review bandwidth allows (different files). T2, T7, and T11 are the heavy tasks (renderer, wizard, guide). Estimated shape: ~13 implementer dispatches + reviews; the frame stays playable throughout, so the owner can `cargo run` at any HEAD.

## Risks, named

1. **Test re-pointing volume** (~310 lib tests) — mitigated by per-task incremental re-pointing; a task that leaves red tests does not close.
2. **The readline seam** — piped protocol regression would break the honesty net; the dogfood gates are the tripwire, TTY-gating the construction is the design.
3. **Reveal-flow surgery** — semantics must not move; assertions about atomicity/order are kept verbatim while presentation re-points.
4. **Width discipline** — the assert-exact-width helper is mandatory in every emitter; ambiguous-width glyphs get pinned fixtures.
5. **Scope creep toward 3.5b** — bot productionization, `why`, and the replay viewer stay out however tempting the seams look mid-redesign.
