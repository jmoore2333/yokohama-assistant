# Phase 3.1a — Factored Action Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Spec:** `docs/plans/2026-07-25-phase3.1-action-interface-spec.md` (v2, reviewed) — this plan is the **3.1a** half (factored core: families + retreat + placement + small families + equivalence + benchmark; discharges the six-figure handover). 3.1b (routes + `is_move_legal`) is a separate later plan. **Branch:** `phase3.1a-action-core`. **Base:** master `b120af6`, SEMANTICS_REV 3.

**Goal:** A factored, lazy `ActionSource` over `&GameState` + `&Rules` that yields move families first and serves/pages/samples within a family without materializing the exploding retreat family — proven equivalent per-family to the frozen `get_legal_moves`, with recorded worst-case allocation bounds.

**Architecture:** New engine-side module `game/search_actions.rs` (flat `mod`/`pub use`), purely additive — `get_legal_moves` and every apply arm are untouched. Retreat gets a direct mixed-radix constructor (never a Vec); placement gets lazy combination construction with per-combination affordability; the already-small families delegate to the existing generators (equivalence by construction). Routes and `is_move_legal` are 3.1b.

**Tech Stack:** Rust, no new dependencies (a ~40-line counting `GlobalAlloc` for the benchmark, `Instant` like `examples/selfplay.rs`; no criterion).

## Global Constraints

- **TDD:** failing test first, run-red, minimal impl, run-green, commit.
- **Per-edit gate after EVERY task:** `cargo test -p yokohama-core` + `cargo clippy --workspace --all-targets -- -D warnings` green. Never `cargo fmt`.
- **No `SEMANTICS_REV` bump; no engine behavior change.** `get_legal_moves` (`legal_moves.rs`) and all `apply_move`/`apply_move_unchecked` arms are READ-ONLY references — do not edit them. If a task seems to need editing one, STOP (re-map signal).
- **`get_legal_moves -> Vec<Move>` surface frozen** (234 consumers); the factored source is additive.
- **The factored module never enters the oracle's import allowlist.**
- **Names:** module `search_actions`, type `ActionSource`/`MoveFamily` (all collision-free at HEAD); do NOT use `Policy` (difftest-owned, 3.2). `MoveFamily` variants carry **owned** snapshots (clone the ≤17-entry `on_board`), never borrows.
- **Enumeration order must match `get_legal_moves` per family:** BTreeMap-canonical everywhere; **FulfillOrder replicates `order_cards_in_hand` Vec insertion order**, never a sorted key.
- **Retreat mixed-radix:** the LAST `on_board` BTreeMap area is the least-significant digit (matches `enumerate_recovery_options` `legal_moves.rs:382-400`).

### Task 2: Retreat family — direct constructor, product len, mixed-radix iter/sample

**Files:** modify `game/search_actions.rs`. **Consumes:** Task 1's `MoveFamily::MovementRetreat`.

**Interfaces produced:** `fn retreat_move(on_board:&BTreeMap<AreaId,u8>, per_area:&[(AreaId,u8)]) -> Move`; `impl` on `ActionSource`/free fns `retreat_len(on_board)->usize` (= `∏(count+1)`), `retreat_iter(on_board)->impl Iterator<Item=Move>` (mixed-radix, lazy), `retreat_sample(on_board,&mut impl Rng)->Move` (independent per-area draw).

- [ ] **Step 1 — failing tests (the load-bearing ones).**
  - **Equivalence:** for random `on_board` snapshots, `retreat_iter(on_board).collect::<Vec<_>>()` equals `enumerate_recovery_options(&player).into_iter().map(|r| Move::ReturnPresidentToHand{recover:r}).collect()` — **same order AND multiset** (mixed-radix last-area-LSB reproduces the generator's BTreeMap-order/ascending-counts).
  - **Product len:** `retreat_len == enumerate_recovery_options().len()` for several distributions incl. the worst case (= 442,368 at the 17×{2,2,2,1×14} 4P state).
  - **Constructor validity:** `retreat_move(on_board, &[(a,2),(b,1)])` then `apply_move_unchecked` is `Ok`; an over-count `&[(a, have+1)]` — the constructor builds the map, `apply_move_unchecked` returns `RuleViolation` (constructor doesn't pre-validate; the arm is the validator).
  - **Sample legality:** 10k `retreat_sample` draws each apply `Ok`.
  - **No materialization:** `retreat_iter().nth(442_000)` and `retreat_sample` on the worst-case state allocate O(#areas), NOT O(product) — assert via a scoped counting-allocator probe that serving one candidate stays under a small bound (e.g. < 64 allocations) regardless of product size.
- [ ] Steps 2-5: run red, implement (mixed-radix decode over `on_board` iter with last area = LSB; `retreat_move` builds the `BTreeMap` from non-zero pairs), green, gate, commit (`feat(3.1a): retreat direct constructor + mixed-radix lazy iter/sample`).
