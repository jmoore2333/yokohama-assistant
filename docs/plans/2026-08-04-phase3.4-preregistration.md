## §2 — THE SCREENING (spec §4)

### 2.1 The declared grid, and the knob values declared BEFORE it ran

Grid = leaf {hand-off, midturn-diag} × c {3 values} × squash scale {2 values} = **12 configurations**, the §4 ceiling. `m` is NOT a screening axis and is pinned at the shipped `greedy::DEFAULT_RETREAT_SAMPLES` = 8; `cap` is pinned at B\* = 750; `k` (worlds) is 1 and §0.4 keeps it there.

**The three `c` values** (UCB1 exploration, parts per million). Grounds — the module's own recorded arithmetic (`mcts.rs`, `DEFAULT_SQUASH_SCALE`'s doc): at N simulations, preferring a once-visited child over an unvisited sibling costs `c·√(ln N)·(1 − 1/√2)` of value, which at the reference N = 64 is `0.5973·c`; the value differences this evaluator actually produces at a decision point are ≈0.13 (median candidate spread 36) to ≈0.31 (max 167) at scale 100. The shipped `c = √2` therefore costs 0.845 — **several times the widest value difference**, i.e. exploration-dominant, near-breadth-first at small budgets, which is the module's stated open question and T3's measured tie-decided 15% → 83% move from c = 0 to c = √2. The grid is chosen to BRACKET that, not to replace it:

| value (ppm) | c | revisit penalty at N=64 | one-line grounds |
|---|---|---|---|
| `100000` | 0.100 | 0.060 | the **exploitation end** — an order below the median candidate spread's value difference (0.13), so value differences decide and the tree exploits |
| `500000` | 0.500 | 0.299 | the **crossing point** — comparable to the WIDEST observed point (0.31), so exploration and exploitation trade off rather than one dominating |
| `1414214` | √2 | 0.845 | the **shipped default and the untuned prototype value** — the exploration-dominant end; included so the grid brackets the default rather than replacing it unmeasured |

**The two squash `scale` values** (in `eval::score` units; `squash(x,s) = 0.5·(1 + x/(|x|+s))`, so `s` is the margin at which the map reads 0.75):

| value | one-line grounds |
|---|---|
| `36` | the **measured MEDIAN candidate-to-candidate spread** at a decision point (`DEFAULT_SQUASH_SCALE`'s doc: median 36 · p90 92 · max 167). A median point maps to a 0.25 value difference instead of 0.13 — the steep, aggressive end |
| `100` | the **shipped default**, whose grounds are recorded in-module (median point → ≈0.13, widest → ≈0.31, "on the steep part of the map rather than in a tail") |

Both declared values sit at or below the shipped scale ON PURPOSE: the only scale direction with measured evidence against it is COMPRESSION (the module records `scale = 1000` rejected for compressing the median point to ≈0.018 — R5's foot-gun in its value form), so the grid spends its two slots where the evidence points and states that it does not test expansion.

### 2.4 How `sims/dec` was measured — a stated runner gap, and the probe that closed it

**The gap:** spec §4 requires sims/dec per configuration and §0.1 requires it per arm, but `CellReport` carries no simulation counter and `examples/arena`'s print layer therefore cannot emit one — `McSearchStats::simulations` exists only per search. Per T8's boundary the runner was **not patched** (this commit touches no `crates/` file); the gap is recorded here as a T9/close-out follow-up candidate rather than fixed under a pre-registration task.

**The probe:** an OUT-OF-REPO scratch binary (scratchpad only, never committed) that path-depends on `yokohama-core`, wraps `mcts::MctsAgent` in an `ArenaAgent` delegate accumulating `last_explanation().stats.simulations`, and reproduces the cell driver's seeding EXACTLY — `SeedSchedule::diagnostic(master)` world draws, `unit_for` seatings, `agent_stream_seed(seed, seat, slot)` keying, invariants ON.

**Its validity check is arithmetic, not assertion:** for all twelve screening configurations the probe's X decision count and X `scored` total equal the cell's printed figures to the unit (e.g. config 2: 11,343 decisions and 3,992,193 scored on both sides; config 1: 10,677 / 3,757,135). A probe that reproduces the deterministic counters exactly is playing the same games, so its simulation counts are the cell's. The same identity holds at the C1 self-play shape (7,802 pooled decisions = 4,076 + 3,726; 2,722,613 scored = 1,432,865 + 1,289,748) and at the C4 shape once the probe's Y beam is set to 16.

**The finding this figure buys, which is exactly what §4 said it would:** at the SAME 750-successor cap, the two leaf rules buy wildly different simulation counts — **hand-off ≈ 17–20 sims/dec, midturn-diag ≈ 117–124 sims/dec, a ≈6.6× ratio.** The hand-off leaf spends most of the budget inside completions. So the leaf axis of this grid is a **mechanism × simulation-count** comparison and not a mechanism comparison, precisely as spec §4 pre-stated; any reading of the leaf result must carry that.

> Calibration ratio **0.980** (X 1261.5 / Y 1287.2 µs/dec over 2202 / 2597 decisions). **2100 is not in the forbidden band 32–128.**

### 6.3 The acceptance test at T9, the `wall-mismatched` label, and the ONE re-calibration

- **The acceptance test is run on C3's OWN output, not on this calibration.** T9 reads the realized X:Y µs/dec from the C3 cell's own per-side walls at N=100 on `…_0007`. Accepted iff the ratio is in **[0.85, 1.15]**.
- **On acceptance:** C3 is a valid wall-matched cell and `W = classify(C3)` enters §7's rule normally.
- **On a miss:** the cell is **labelled `wall-mismatched`**, it **carries NO decisive force**, and the ADR says so wherever C3 is quoted. Because §7's adoption rule is a CONJUNCTION requiring `W = ABOVE`, **a wall-mismatched C3 cannot deliver adoption** — the outcome is the pre-registered default (S1 retained) with the wall axis recorded as unresolved. This consequence is pre-declared here so it cannot be re-argued after the fact.
- **Exactly ONE re-calibration is permitted** (spec §5's C3 row). Its procedure is fixed now: re-run §6.1's ladder unchanged — same shape, same N=10, same screening master `0x5CEE_2026_0804_0002`, same statistic, same band — to a NEW S_wall, then re-run C3 ONCE at that S_wall on the SAME adjudication master `0xA3E1_2026_0804_0007`. The re-calibrated S_wall must also lie outside 32–128; if the ladder wants a cap inside the band, the re-calibration STOPS and the ADR records `wall-mismatched, calibration blocked by the forbidden band`.
- **A second miss ends it.** C3 stands labelled `wall-mismatched`, no third calibration is run, and the ADR records that the wall axis could not be matched on this laptop — with map §1.3's caveat beside it (a wall result here is an implementation-efficiency fact, not an architecture ceiling).
- Both the calibration and the acceptance test are on WALL, which is load-sensitive by construction. That is why the statistic is an in-cell RATIO of two sides measured on the same clock during the same games, and why nothing asserts an absolute µs figure anywhere.

## §7 — The budget ladder, the bands, and the notes

### 7.1 The budget ladder

**Ladder = {750, 1500, 3000}** (spec §0.1-S2 / §5). It is the pre-registered routing for the S2 completion-failure surface: a cell invalidated by an `ArenaError::CapReached` whose plausible cause is a starving arm re-runs ONCE at the **next HIGHER** rung with the starving arm labelled — UP, not down, because in a matched-budget experiment starvation is the likely cause and a lower budget makes it worse. ## §8 — THE DECISION RULE, quoted VERBATIM from spec §0.1

Everything in this section is a verbatim quotation of `docs/plans/2026-08-04-phase3.4-search-arch-spec.md` §0.1. It is reproduced here so the rule is fixed in the same commit as the knobs and masters it will be applied to. **No paraphrase, no re-ordering, no omission.**

> **Definitions.** `classify(cell)` ∈ {ABOVE, BELOW, CONTAINS}: a `Bootstrap` interval with `lo > 0.5` (strict) is ABOVE; `hi < 0.5` is BELOW; anything else — including an endpoint landing exactly on 0.5 (lens 1 S1) — is CONTAINS. A `RefusedZeroWidth` all-won is ABOVE, all-lost is BELOW; constant-interior is CONTAINS **only after the differing-play precondition passes** — the two seatings of ≥90% of units must have produced differing games, checked by terminal-digest inequality as the stated proxy (lens 1 M6 / critic R6: two effectively identical agents produce constant-interior trivially — map §8 row 14's instrument-dead mode); a precondition failure is a harness bug, not an outcome. `NO_UNITS` or any other shape: harness bug.

> **Surfaces, evaluated per arm and per cell in this precedence BEFORE classification (lens 1 M3): harness-bug → completion-failure → null-gate.**
> - **S1 harness bug:** malformed outcome anywhere → halt, investigate, no adjudication.
> - **S2 completion failure:** any game in a cell returning `ArenaError::CapReached` INVALIDATES that cell (never dropped, never silently scored). Attribution: if the arm whose decisions show nonzero `budget_starved_decisions` is the plausible cause, the routing is **UP the pre-registered ladder** — that arm's cells re-run once at the next higher budget with the starving arm labelled (lens 1 M10: in a matched-budget experiment starvation is the likely cause, and "fall to a lower budget" makes it worse); failure at the top of the ladder → the ADR records `completion-failure at matched budgets` as the finding for that comparison. A cell with nonzero starvation and no cap-hit stands but is **never read as a clean matched-budget adjudication** (lens 1 S4 / critic §7.3).
> - **S3 null-gate:** each adjudication master's same-master null control (§5's C1 for arm 1, C1′ for arm 2 — lens 1 M4: a BINDING arm without a null control re-admits the hazard the control exists for) must return **`IntervalOutcome::Bootstrap` whose interval CONTAINS 0.5 with nonzero realized unit variance** — the `arena_gate` null clause's own wording. **Any `RefusedZeroWidth` at a null, or a zero SE, FAILS the gate** (lens 2 M1: v1's "excludes 0.5" was satisfied by exactly the degenerate refusal the control exists to catch). On a failure: triage first (run the capped-S1 self-null on the same master to separate an X-machinery defect from a master excursion — lens 1 N2), then that arm's primary + null re-run ONCE at the pre-declared alternate master, **REPLACING the failed arm's cells** (never augmenting — lens 1 S13; the ~5% false-trigger rate buys one pre-declared extra look, stated); a second failure → harness-defect ticket, and the ADR records "the instrument could not resolve a zero edge on two masters".

> **THE DECISION (after surfaces clear).** Let `J = (classify(C2 arm 1), classify(C2 arm 2))` and `W = classify(C3)` (the wall cell, whose opponent is the SHIPPED `lookahead-v1:b=4` — deliberately, so no adoption can rest solely on capped-S1 comparisons), and let `C0-certified` mean C0's interval ⊆ **[0.44, 0.56]** (an equivalence band of ±0.06 ≈ ±42 Elo, under half the measured ladder rung spacing; N = 200 makes the band satisfiable — a true-null interval spans ≈ ±0.046 — and a miss means the capped arm is not certified as the shipped rung's proxy; lens 1 M9: v1 read non-rejection at N=100 as equivalence and wired C0 to nothing).

> > **MCTS-v1 is ADOPTED as the serious-strength architecture for 3.5 iff `J = (ABOVE, ABOVE)` AND `W = ABOVE` AND C0-certified. In EVERY other post-surface outcome, S1 is RETAINED — with incumbency stated in the ADR as a PRE-REGISTERED DEFAULT, never a merit finding** (lens 1 M1/M2: v1 let the node axis adopt alone with the wall merely printed, contradicting the map's "they can rank differently", and its no-edge tie-break named a quantity the wall-matched cell equalises by construction — both repaired by this single conjunctive rule).

> The named finding per non-adoption outcome (each pre-registered so the ADR writes itself mechanically): `J=(ABOVE,ABOVE)` with `W=CONTAINS` → *per-node superiority at wall parity*, recorded, 3.5 commitment stays with S1 pending a wall-axis disposition (the named cheap follow-up: one re-calibrated C3); `J=(ABOVE,ABOVE)` with `W=BELOW` → **the axes rank differently — the map-anticipated headline finding**, S1 retained on the pre-registered default, the map §1.3 caveat recorded beside it (a wall result on this laptop is an implementation-efficiency fact, not an architecture ceiling — lens 1 N1); `J=(BELOW,BELOW)` → S1 retained on the merits, with W recorded (a `W=ABOVE` there is again the axes-disagree headline); any J containing CONTAINS, or `(ABOVE,BELOW)`/`(BELOW,ABOVE)` → **no robust edge at this N** — the arm-disagreement case is named an accepted consequence (a one-master sweep plus a one-master interior is NOT robust evidence, deliberately — lens 1's §0 answer 1), and the ADR reports the **JOINT detectable edge** (lens 1 M5: the conjunction's operating characteristics are stated, not implied — per-arm power ≈ 0.98 at θ = 0.60 under the measured Var_pair ≤ 0.119 at N = 200, joint ≈ 0.97; the 3.2 policy's 97→200 rounding is what buys the conjunction its power). If C0 is not certified, an otherwise-adopting outcome still adopts on `W` (the shipped-rung cell) but the ADR's node-matched claim carries the qualified wording "against a budget-limited S1 whose C0 read [interval]" (lens 1 M9). MCTS-v1 is preserved as a labelled diagnostic in every outcome (the T7 disposition — nothing is deleted).

**Orientation, also verbatim (§0.1):** *"X = MCTS-v1 in every cell; reversing it would invert every branch, and it is not reversed."* Every registered cell in §3.2 seats MCTS-v1 as X — except C0, whose X is the capped S1 arm by §5's own table, because C0 is a validation of that arm and not an adjudication of the architecture.
