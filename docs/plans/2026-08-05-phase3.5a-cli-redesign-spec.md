**In:** the composed-frame redesign (all player counts); the dashboard; V3 tiles; the view surfaces and card indexes; the decision zone; the wizard and reveal-flow redesign (live recording posture, R6); the readline layer; input-grammar unification; the F1–F11 fixes; the guide pair rewrite; test re-pointing.

## 2. Architecture

- **`screen_model.rs` (new):** typed description of a frame — `TileModel` (name, token, site strip, pawns, marks), `Panel` variants (players/tracks/achievements/hand), `DecisionModel` (phase chain position, deciding-line, options with kind/fee/reason, not-offered rows), `IndexModel` (card grids, dim/annotation state). Built from `&GameState` + `Rules` + session context by pure functions; **no ANSI anywhere in this module.**
- **`render_ansi.rs` (evolves `render`/`screen`):** consumes the model; owns glyphs, color, layout constants (`FLOOR_2P = 200×50`, `TILE_W = 30`, per-count arrangements); every tile/card emitter carries the width assert (§0.4). `style.rs` stays the single ANSI authority; `visible_width` stays the measurement everywhere.
- **Piped path:** unchanged line protocol from the same models' plain-text projections; the composed frame remains TTY-only exactly as today.
- **Input:** one prompt loop; TTY reads via the line editor (§0.9), pipes via plain reads; a unified `CardPrompt` helper implements §0.2/§0.6 (menu numbers, ids, names, `?`, echo-back, already-placed) and is used by the wizard, reveals, and in-game pickers alike.
- **Dependency note:** the line editor is the one new dependency, CLI crate only; flagged to the owner at PR with license named.
