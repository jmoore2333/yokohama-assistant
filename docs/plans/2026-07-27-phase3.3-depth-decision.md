### 2.4 Tie randomization on BOTH sides — verified against the shipped code, not assumed

§4.1 requires *every* tie point randomized on both sides. T5 landed it; this task re-verified it at HEAD by code read plus the pins that hold it:

| tie point | shipped site | applies to | pin |
|---|---|---|---|
| root argmax | `lookahead.rs` `LookaheadAgent::choose` → `ctx.ties.pick(TieSite::Root, tied.len())` | **both** schemes (one `choose`, scheme-agnostic) | `the_root_argmax_draws_over_the_whole_tied_set` |

| quiescence extension | `Run::atomic` → `TieSite::Extension { root, depth: free_used, branch }`, with `descend_branch` separating sibling lines | **S2** | `a_tie_draw_is_one_keyed_word_and_is_world_common` (site/branch separation, incl. the T5-review sibling case) |

All four call sites (the three above plus `greedy`'s) share one `uniform_index` primitive — Lemire multiply-shift, exactly one word per draw whatever the tie count — and the word is **keyed**, not consumed from the play stream, so a tie draw is identical across K worlds.

**One honest scoping note, recorded because it is a *deliberate* asymmetry and a reader will otherwise find it and wonder.** Both schemes also have an inner **value aggregation** that is first-wins among equals — `Run::atomic`'s max over expanded children, and `complete_turn`'s equivalent. That is not a tie *point* in §4.1's sense and is documented as such in-module: it selects no move (every child is expanded and only a scalar is propagated), so unlike an argmax or a beam cut it cannot express a preference for the enumeration's first element. The three sites that *do* select are all randomized, on both sides.

## 4. Realized `Var_pair` and the post-hoc detectable edge

### 4.1 The realized variance, with the arithmetic

The realized unit vector is `155 × 0.0` + `43 × 0.5` + `2 × 1.0` (n = 200):

```
Σx   = 43(0.5) + 2(1.0) = 23.5           θ̂ = 23.5 / 200          = 0.117500   ✓ matches the report
Σx²  = 43(0.25) + 2(1.0) = 12.75
SS   = Σx² − n·θ̂²      = 12.75 − 200(0.1175²) = 12.75 − 2.76125 = 9.98875
Var_pair (population, /n)     = 9.98875 / 200 = 0.04994375   → 0.049944  ✓
Var_pair (sample, /(n−1))     = 9.98875 / 199 = 0.05019472   → 0.050195  ✓
sd (sample)                   = √0.05019472  = 0.2240418     → 0.224042  ✓ matches the unit-t row's sd
SE(θ̂) = √(0.05019472 / 200)  = 0.015842
```

**The caveat §4.1 required is discharged — and the T7 review corrected this section's first draft, which had compared the wrong variances.** The realized `Var_pair = 0.0502` is the variance AT the observed θ̂ = 0.1175 — an outcome-dependent quantity (a unit vector concentrated far from 0.5 has small variance *because* the result was one-sided; 155 of 200 units were 2–0 to S1). A power statement about detecting an edge NEAR THE NULL must use the variance AT THE ALTERNATIVE, which is what the pre-registered 0.1225 approximates. The cell's own data supplies the honest comparator: the implied within-unit correlation is ρ = 2·Var/(θ̂(1−θ̂)) − 1 = **−0.0319** (cross-check: 43/200 = 0.2150 split units against 2θ̂(1−θ̂) = 0.2074 expected under independence), which puts the near-null pair variance at (0.25 − δ²)(1+ρ)/2 ≈ **0.1188** — within 3% of the pre-registered 0.1225. **The sizing assumption was essentially right**, neither favourable nor conservative; the first draft's "2.44× smaller / over-powered" reading compared an outcome statistic to a design constant.

### 4.2 The post-hoc detectable edge, by inverting `pairs_needed_for_mme`

`pairs_needed_for_mme(θ, var) = ceil(7.848878 · var / (θ − 0.5)²)` (`game/arena/stats.rs`; the constant is `(z₀.₉₇₅ + z₀.₈₀)² = (1.959964 + 0.841621)²`, two-sided α = 0.05 at 80% power). Solving for the edge this cell's realized N and variance actually buy:

```
δ = √( 7.848878 · Var_pair / n )
  = √( 7.848878 × 0.050195 / 200 )        [sample divisor]
  = √( 0.39397443 / 200 ) = √0.00196987
  = 0.044383
```

**That δ is computed at the θ̂-realized variance and is NOT a power statement about near-null alternatives** (T7 review): the variance in a power calculation belongs to the ALTERNATIVE being detected. Self-consistently, with the cell's implied ρ = −0.0319: solve δ² = 7.848878·(0.25 − δ²)·(1+ρ)/2 / 200 → δ = 0.0683, so the **post-hoc detectable edge at 80% power is θ ≈ 0.568 (equivalently 0.432)**, at a near-null pair variance of ≈ 0.1188 — close to what the pre-registered 0.1225 would give (θ = 0.5693). The θ̂-variance figure (δ = 0.0444 → "θ = 0.5444") is retained above only as the arithmetic the first draft ran; it understates the detectable edge and is superseded.

**Self-check of the inversion** (it must round-trip to the N that was run):
`ceil(7.848878 × 0.050195 / δ²) = 200` — **exact by construction with the unrounded δ**; with the printed 6-dp δ the quotient reads 200.0075 (T7 review: the displayed intermediate rounds; the round-trip property holds for the exact value).
**Independent check of the formula itself:** at the spec's own numbers `ceil(7.848878 × 0.1225 / 0.10²) = ceil(96.149) = 97`, reproducing the value pinned by `pairs_needed_matches_e2s_table`. ✓

Two comparisons worth recording:

| quantity | at the pre-registered `Var_pair` 0.1225 | at the cell-implied NEAR-NULL variance ≈ 0.1188 (ρ = −0.0319) |
|---|---|---|
| detectable edge at N = 200, 80% power | θ = 0.5693 | **θ ≈ 0.568** |
| units needed for the named MME 0.60 | 97 (→ rounded to 200 by 3.2 policy) | **92** (Var at θ=0.6: 0.24·(1+ρ)/2 ≈ 0.1162) |

*(The first draft's third column used the θ̂-realized 0.050195 — an outcome statistic, not an alternative's variance — and read θ = 0.5444 / 40 units; corrected at the T7 review.)*

And the observed effect against the corrected yardstick: the distance from the null, 0.3825, is **5.6×** the detectable edge δ = 0.0683 (and z = (0.5 − 0.1175)/SE(θ̂) = 0.3825/0.015842 = **24.1** against the observed-variance SE). The interval's near end, 0.1500, is 0.35 from 0.5 — about **five times** the smallest edge the cell was powered to see. This is not a marginal call under either variance convention.

## 5. THE DECISION, applied mechanically

**Rule branch taken — the FIRST branch, verbatim:** *"bootstrap interval entirely below 0.5 → turn-boundary confirmed."*

The primary interval is `IntervalOutcome::Bootstrap { lo: 0.087500, hi: 0.150000, b: 10000, resample_seed: 0xfb501c89c30d1228 }`. `hi = 0.150000 < 0.5`, so the interval is **entirely below 0.5**. It is a real two-sided bootstrap interval, not a refusal, so none of the degenerate branches (all-lost, all-won, constant-interior-at-0.5, other-constant-interior→harness-bug) is reachable; the rule's other branches are not consulted.

> ### ✅ **DECIDED: turn-boundary look-ahead is CONFIRMED. S2 atomic-with-quiescence is the loser and stays a labelled diagnostic.**
>
> `Lookahead-v1` keeps §4.2's shape — **S1, hand-off = `current_player` transition (a finished game counts), B = 4 as a knob, §3.3 candidates, §3.2's tie-break at every tie point.** The `atomic-diag-v1` arm ships behind the contestant surface as 3.4's raw material, exactly as §4.1 directs; only the winner is the preserved rung.

**Three things this decision deliberately does NOT say.**
1. It does not say S2 is a bad idea *in general* — it says S2 **at d = 2, under evaluator v1, at K = 1, at 2P, on this master** loses to S1 at B = 4. Depth-semantics choice is conditional on the evaluator it is built over, and the evaluator is v1.
2. It does not claim S1's margin is *this* large in general. θ̂ 0.1175 is one cell on one committed master; the honest general claim is the direction plus the interval, with the master named.
3. It is not a *strength* claim about Lookahead-v1 against anything outside this pairing. The promotion gate (§0.1) is a separate, two-armed run and this artifact does not anticipate it.

### 6.3 The prefix trap — recorded because it nearly went into this artifact

The same harness over the **first 5 units (10 games)** of the same master reads `nodes ratio S2:S1 = 1.0681`, `scored ratio 1.0072` — *near parity*, reproducing the module's fixed-150-points figure and flatly contradicting the full-cell numbers above. Nothing changed but N.

The mechanism is the one `lookahead.rs` already warns about in the strongest terms it has: **S2's per-decision cost is so heavy-tailed that a mean over a few games is not a statistic** (its own re-measure records median 40.1 µs against a max of 2,583,353 µs — 2.58 seconds in a single decision, with 471,632 nodes and 464,686 free-extension steps in that one decision, 40× S1's worst). A small prefix samples the median; the cell samples the tail. The wall figures say the same thing in the same direction from the same runs: the arena cell itself costs **437.3 ms/game over its first 40 games** (the §7 determinism run, same binary and command at N = 20) against **1,812.7 ms/game over all 400**.

**The reading this forces on §6.1's prior figures:** the module's 150-fixed-point row is not wrong, it is *under-sampled for this question* — 150 points drawn from one Greedy-v1 walk cannot contain S2's tail, and it is the tail that decides the cost comparison. The self-play-means row (1.93× on nodes) was directionally right and quantitatively low. All three, including the numbers above, remain **observations under a named harness** and none is a bound.

## 8. What would reverse this

Named so a future reader knows what to re-run rather than re-litigating from prose. Each item is a *condition of the finding*, not a doubt about it.

1. **A different evaluator.** The decision is conditional on the frozen `WeightTable::V1` (`weights=-2162047371061899018`). Weights are first-order (research R1-2: re-weighting moved held-out AUC 0.5646 → 0.6714 while a term-set redesign moved 0.008), and depth semantics are a claim about what the *evaluator* can see at a horizon. **An evaluator v2 re-opens this experiment**, and the per-controller version rule (§0.5) already says both controllers' figures stop being comparable when weights move.
2. **A different d or B.** This is S2 at **d = 2** against S1 at **B = 4**. S2 at d = 3 was measured (by R3) at 26,225 nodes/decision mean and 140,226 on one decision — a different cost class entirely, not a re-run of this cell. B is a knob and §4.2 keeps it one.
3. **K > 1.** Both arms ran at K = 1. §4.3's revisit trigger is the determinization cell, not this one; if K moves, the hand-off/turn-completion channel that distinguishes the schemes changes with it.
4. **Player count.** 2P only. 3–4P strength cells are OUT of 3.3 (§1) and there is no measured `Var_block` to size them from (map §8 row 16).
5. **Cost matching.** The research notes (§3, line 85) described the anticipated confirming experiment as "cost-matched"; the governing pre-registration (spec §4.1) carries NO cost-matching clause, so the cell as run is faithful to its registration — but the un-matched budget ran in the LOSER's favour: S2 consumed 3.27× the nodes and 10.22× the scored successors per decision and still lost decisively, so a budget-matched rematch (S1 granted equal compute — a larger B, or K > 1) could only widen S1's case on these figures. What could genuinely reverse the count comparison is a TRANSPOSITION-equipped S2 (within-turn move-order convergence amortising atomic search) — the named 3.4 shape, unmeasured here.
5. **A fresh master.** One committed diagnostic master. The interval's near end sits ~8 δ from the null, so a master effect of the size that could flip the *direction* is not plausible on this evidence — but the honest form of that sentence is "would need re-measuring", and an OS-entropy re-run at the same N is the cheap way to buy it (~12 min).
6. **A change inside `Run::atomic`.** S2's own doc records that the T5 evaluate-only leaf reorder cut its nodes 76.6% at fixed points and moved its self-play mean turns 51.0 → 33.5. A further S2 optimization changes the *cost* side of any future no-edge adjudication — it does not change *this* one, which was decided on the interval and not on cost.
