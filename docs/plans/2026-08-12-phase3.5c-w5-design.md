## 1. Seam 1 — the retype

### 1.1 Types

`BotSeats.seats: Vec<Option<RolloutPolicy>>` → `Vec<Option<Contestant>>` (`Contestant` is `Copy`, stats.rs:144). Rung seats become `Contestant::Policy(p)`. `BotChooser::choose` takes `contestant: Contestant` where it took `policy: RolloutPolicy` (bot.rs:248). The `seed: u64` field, `decision_seed`, `is_bot`, `without_bots` are untouched.

### 1.2 Eligibility: eligible ⟺ legacy rung, or explainable evaluator

CLI-eligible contestants: **`Policy(_)`** (legacy compatibility — every existing save resumes), **`GreedyV1`**, **`LookaheadV1`**. **`MctsV1` and `AtomicDiag` are refused by name** — they are labelled diagnostics (mcts NOT adopted per the 3.4 ADR; atomic-diag is the S2 diagnostic arm), and the CLI must not become a second diagnostic surface. The refusal follows the probe's W1-C precedent (parse via the core grammar, then narrow with a named refusal) and lands as the **downgrade-to-HUMAN-loudly arm**, with wording that names the contestant as a diagnostic not available as a CLI bot — the game always loads; the seat degrades loudly. The principle stated once: every evaluator seat the CLI will run must be `why`-explainable; rungs are grandfathered and `why` names why they cannot explain (§2.4).

### 1.3 One decide path, shared by the pump and `why`

A single CLI function (new module `bot`-adjacent, implementer's layout call):

```
decide(contestant, state, rules, seat, decision_seed) -> Result<Decision, BotError>
```

where `Decision` carries the chosen `Move` plus, for evaluator arms, the explanation parts (`Explanation`, continuation, root ranking, `SearchStats`).

- **`Policy` arm:** the existing `HonestChooser` chain **byte-identical** (bot.rs:267–293: observe → two `splitmix64` steps splitting `decision_seed` into sampler/pick seeds → `BeliefSampler::from_view` K=1 → `DecisionHandle` → `ChaCha8Rng` → `policy.pick`). No explanation parts — `why` refuses rung seats.
- **Evaluator arms:** observe → construct the **concrete** agent exactly as `Contestant::build`'s arm does (stats.rs:484; for lookahead that is `LookaheadAgent::with_knobs`/the capped constructor with `WeightTable::V2`, seeded by `decision_seed`) → `agent.choose(&view, rules)` → read `last_explanation()`/`last_continuation()`/`last_roots()`/`last_stats()` (lookahead.rs:2071–2116; greedy has `last_explanation` only, greedy.rs:727 — its `Decision` carries an empty continuation/ranking and `why` renders the leaner block).

Why concrete agents and not `Contestant::build`'s `Box<dyn ArenaAgent>`: `DecisionReport` is `{ mv, volume }` (arena.rs:309) — the trait object exposes no explanation accessors, and `why` needs them. Why ONE path for both callers: reconstruction-identity becomes **structural** — `why` re-runs literally the function the pump ran, so a divergence class (pump constructs one way, `why` another) cannot exist. The residual drift risk (CLI construction vs core's `build`) is closed by a **drift-pin test**: at fixed seeds over a small battery of states, `decide`'s move equals the move chosen by `Contestant::build`'s boxed agent for every eligible evaluator arm. (This pin also catches a future weight-table promotion moving `build` but not the CLI mirror.)

The bot's engine-refused-move lockdown, `BotError` classification, `PUMP_MOVE_CAP`, and both pump call sites (repl.rs:504, repl.rs:2573) are unchanged.

**Not claimed, stated so nobody chases it:** the CLI bot is NOT bit-stream-identical to an arena seat. The arena holds one agent per game whose RNG stream advances across decisions; the CLI builds a fresh agent per decision keyed by `(bot_seed, events.len())` — the scheme bot.rs's module doc mandates (serializable resume). Both are honest (view-only input, keyed determinism); they are different determinism schemes. `why` reproduces the CLI bot exactly **because** it shares the CLI's keying; nothing reproduces an arena game through the CLI, and nothing needs to.

### 1.4 Provenance out (seat_provenance)

bot.rs:170's `ControllerProvenance::from_policy(*p, Some(self.seed))` becomes `contestant.provenance(Some(self.seed))` (stats.rs:411). For `Policy` arms `Contestant::provenance` **delegates to `from_policy`** — byte-identical for every existing rung seat, pinned by a golden (a rung-seat `SeatProvenance` serializes to the same bytes before and after the retype). Evaluator knobs ride `SeatProvenance.params` (`BTreeMap<String, i64>`, record.rs:106) via the same descriptor machinery the arena uses; **`LookaheadV1 { cap: None }` emits no `cap` key** (stats.rs's absent-cap rule) — pinned, since absence IS the uncapped identity on the preserve-list. No record-schema change; `RUN_PROVENANCE_SCHEMA` stays 1.

### 1.5 Resume in (from_provenance) — `from_parts`, not bare-name reparse

Today bot.rs:202 reparses `seat.controller` (a bare name) through `RolloutPolicy::from_str_name` — lossless only because the wizard writes exclusively default knobs. After the retype that would be a silent defect: a recorded `lookahead-v1` seat with `b=8` in `params` would reparse to `b=4`. So resume reconstructs from **both** stored halves via a new core helper:

```
Contestant::from_parts(name: &str, params: &BTreeMap<String, i64>) -> Result<Contestant, String>
```

— the inverse of `Contestant::descriptor()` (stats.rs:449), with absent `cap` key ⟹ `cap: None`, unknown name/key/value a typed error naming what was seen, round-trip pinned for every arm × knob-presence combination. The W1-deferred refusal-text repair rides along on the grammar side: `parse_policy`'s fall-through refusal (grammar.rs) learns to name the contestant string it saw, `from_parts` adopts the same naming discipline from birth, and the W1 battery rows covering that error text update with it (an owner-visible error-text change, deferred to W5 by the W1 fix wave exactly so it would land here). The resume lookup then:

- `CONTROLLER_HUMAN` → `None` (unchanged);
- `from_parts` OK + eligible → the seat's contestant;
- `from_parts` OK + diagnostic (`MctsV1`/`AtomicDiag`) → HUMAN loudly, wording per §1.2;
- `from_parts` Err → the existing unknown-controller HUMAN-loudly arm (bot.rs:220–227), its warning now carrying the error's text so the message names what was actually seen;
- recorded `SeatProvenance.version` ≠ the current controller's version const, or any recorded param differing from the resumed contestant's freshly-derived `descriptor()` params → **warn loudly per differing field, do not refuse** (the game stays playable; the bot plays under the current build; `why` handles the honesty side per §2.3). The descriptor carries identity keys beyond the construction knobs — `eval_impl`, the `weights` table digest, greedy's `placement_cap` — so this one generic comparison catches weight-table and eval-impl drift without key-specific logic. `from_parts` itself consumes the construction keys, accepts the known identity keys without checking them (the caller's comparison is the checker), and errors on anything else. Never fires inside one binary — exists for cross-build resumes.
- conflicting recorded stream seeds → unchanged warning (bot.rs:209–217).

`bga-human` seats keep flowing through the unknown-controller arm as today (imported records resume as human seats, loudly) — correct behavior, untouched.

### 1.6 Alternatives rejected

CLI-local contestant enum (re-implements the grammar; drifts from core — the W1 parser exists precisely so consumers don't do this). Long-lived agents held in the session (non-serializable `ChaCha8Rng`; breaks save/undo — bot.rs:21–30's own argument). Dyn-only decide path (no explanation accessors; `why` impossible). Bare-name resume (silent knob loss, above). Storing the grammar string in `controller` (diverges from the name+typed-params record convention, record.rs:70–78, for no gain).

## 2. Seam 2 — `why`

### 2.1 Grammar and addressing

`why` — the most recent bot-made move. `why <n>` — the move at **the log's own printed index** (`log_text` prints the 0-based event index verbatim, repl.rs:3179–3189; `why` adds no numbering scheme, it reuses the one the user already sees). Both forms dispatch in the repl like `suggest` (`&self`, read-only).

### 2.2 Semantics: reconstruct by replay, refuse on mismatch

For event index `n`: the decision state is `state_at(record, n)` (§3 — the state after the first `n` events, i.e. the state the bot decided IN); the mover is that state's `current_player`; the decision key is `decision_seed(bot_seed, n)` — the same `(bot_seed, events.len())` keying the pump used when it appended event `n`, which is what makes reconstruction exact. `why` calls §1.3's `decide` with the seat's recorded contestant and **asserts the reconstructed move equals the recorded event's move**. On mismatch it **refuses**, naming both moves and both version consts (recorded `SeatProvenance.version` vs current).

The mismatch-refusal is load-bearing three ways: it is a per-invocation determinism check (a keying regression surfaces as a `why` refusal, not a silent wrong explanation); it resolves the mid-history-downgrade ambiguity by construction (a seat downgraded to HUMAN mid-session has human moves under a bot-named provenance — no per-event attribution exists and no new record kinds are allowed, but reconstruction mismatches on exactly those moves and refuses rather than fabricating an explanation); and it keeps `why` honest across builds (a record from an older impl version reconstructs differently → refusal naming the versions, never a wrong table presented as "why the bot moved").

### 2.3 Refusal table (all typed, all named, `suggest`'s four-refusal style)

| Case | Answer |
|---|---|
| live mode | live tracking has no bot seats — nothing `why` can explain (live saves drop bot seats loudly already) |
| no bot move exists yet (bare `why`) | says so |
| `n` out of range | names the valid range |
| event `n` is a reveal, not a move | says which |
| event `n` is a human seat's move | points at `suggest` (the OD-4(i) split: bots → `why`, your move → `suggest`) |
| mover's contestant is a `Policy` rung | "sampled, not valued — a rung pick has no explanation"; names the rung |
| reconstruction ≠ recorded move | §2.2's mismatch refusal, both moves + both versions named |

Game over is NOT a refusal — post-game `why` is exactly the checkpoint's use (`suggest` refuses game-over because there is nothing to advise; `why` explains history, which survives the end).

### 2.4 Output

Header: seat + contestant echo (name@vN{knobs} — §4.2 makes the composer public) + `event <n>` + the decision seed + "reconstructed by replay under" the current impl consts (`EVAL_IMPL_VERSION`, the controller's const), plus the version-mismatch warning line when the record's stored version differs. Body: **`suggest`'s renderer through its existing budget seam** (`render_suggestion_within`, suggest.rs:471) — the move, the principal continuation, the term-by-term explanation table, runner-ups with margins, the honesty/ply-cap notes. The table is not forked; `why` and `suggest` render through one implementation, refactored only as far as sharing requires (a header-parameterization, not a rewrite). Greedy seats render the leaner block (explanation table, no continuation/runner-ups). Sized to `frame_width` like `suggest`.

### 2.5 Properties, each pinned

`&self` read-only: applies nothing, records nothing, autosaves nothing. Byte-identical on repeat at the same position (same key ⟹ same bytes; the `suggest` precedent). Works after game over. And the **every-move pin** — the executable form of OD-4(i) clause (b): play a seeded human-vs-bot game to completion in-test, then for EVERY bot-made event index, `why` reconstructs and equals the recorded move (zero refusals over the whole game). Plus one refusal-path test per §2.3 row.

## 3. Seam 3 — the substrate

One additive core helper in `game/record.rs`:

```
pub fn state_at(record: &GameRecord, k: usize, rules: &Rules) -> Result<GameState, ReplayError>
```

= the private `rebuild_initial_state` (record.rs:392) + `replay_from(&initial, &record.events[..k], rules)` (record.rs:377). `state_at(record, 0)` is the post-setup initial state; the decision state for event `n` is `state_at(record, n)`. Documented against the off-by-one explicitly. Error: `ReplayError` with `event_index` relative to the record (the slice-relative trap session.rs:298–307 documents is avoided here because the slice starts at 0). `k > events.len()` is a typed error, not a clamp.

**Why core and not the CLI:** three call sites already hand-roll the rebuild-then-fold preamble (`Session::load` session.rs:306, `Session::undo`'s else-branch via `replay`, `eval_probe::snapshot_game` eval_probe.rs:1845), and the amendment's D2 harness section names `record::replay_from` reuse for replay-to-root — `state_at` is that reuse point's record-level face, serving `why` now and the deferred viewer, T14's agreement instrument, and the D2 harness later. **Additive only**: no semantics, no `SEMANTICS_REV`, no oracle contact, no existing caller refactored in this PR (retrofitting `Session::load` onto it is named as an optional follow-up, kept out of this diff for risk containment). Cost: O(k) checked applies per call, trivial at CLI scales (a few hundred events, µs–ms each).

Not built: state caching in the session (violates the history-free principle for no measured need); a CLI-side copy of the preamble (a third duplication, and the wrong side of the boundary for the later core consumers).

## 4. The provisional default, and the echo

### 4.1 The default bot seat

Bot seats configured by the wizard get **`Contestant::LOOKAHEAD_V1_DEFAULT`** (stats.rs:353 — uncapped, b=4/k=1/m=8, `WeightTable::V2`), referenced as the core const: no string, no parse at the wizard site (wizard.rs:659's hardcoded `FAMILY_WEIGHTED_DEFAULT` is the line that changes). This is the point of the minimal cut — the owner's two D2 layer-1 diagnostic games play the actual production-intent V2 controller and inspect it with `why`.

**PROVISIONAL, in-source and here:** at D1's identity freeze the default becomes the frozen champion constructed from explicit knobs recorded in the pre-registration — never from `*_DEFAULT` constants (D1's rule). The const carries that comment; this line of this doc is the pointer the freeze work will follow. Until then `LOOKAHEAD_V1_DEFAULT` is itself frozen identity (D1: the shared default constants may not move without an owner ruling), so the provisional default cannot drift silently.

**No picker.** The wizard's bot question stays "which seats are bots" — difficulty levels and per-seat contestant choice are OUT (OD-4(i)). The wizard summary line (wizard.rs:1238–1250) renders the default contestant's echo so the configuration is visible. Resume naturally round-trips any eligible recorded contestant (§1.5) — a consequence of the preserve-list, not a documented configuration surface.

### 4.2 The echo goes public

`contestant_echo` (private, stats.rs:1295, format `name@vN{k=v,…}`) is promoted to a public method on `Contestant` for the CLI's wizard summary, `why` header, and resume warnings. The `examples/arena.rs:233` private duplicate delegates to it (it already delegates parsing); **the `contestant_golden` test's independent composer stays independent by design** (it exists to catch echo drift, and a test that delegates to the thing it checks pins nothing). The echo is a display form, deliberately NOT the parse grammar (`name:k=v,…`) — documented on the method so nobody expects `from_str_name(echo(..))` to round-trip.

### 4.3 The freeze-time TODO, recorded not enacted

`suggest` today constructs `LookaheadAgent::new(rules, stream_seed)` at constructor defaults (suggest.rs:319) — behaviorally the same contestant as §4.1's default, reached by a different construction. W5 does NOT touch it (minimal-cut discipline; `suggest`'s determinism pins stay byte-identical). At D1's identity freeze, both this default and `suggest`'s construction move to the frozen champion identity in the same commit — recorded here so the freeze checklist inherits it.

## 5. Blast radius and test strategy

**Preserved pins (must stay green unchanged):** `decision_seed`'s value pin (bot.rs:329); the unknown-controller and conflicting-seed warnings (bot.rs:362, :410); the live-save bot-drop warning (repl.rs:7167); `suggest`'s four refusals and byte-identity; the piped dogfood's honesty properties.

**Behavioral change owned out loud:** wizard-configured bot seats now run `lookahead-v1` instead of the family-weighted rung. Every test that pinned bot behavior through the wizard default (moves, panels, turn-review content, dogfood transcripts) re-points with the change named per test. Bot decisions get slower (search vs sampling — release ~2–3 ms/decision against ~µs; debug proportionally); the per-edit and release dogfood walls get re-measured and machine-tagged, not assumed. Tests that need the old rung behavior construct `Contestant::Policy(FAMILY_WEIGHTED_DEFAULT)` seats explicitly — the rung is not deprecated, it is just no longer the default.

**New pins (the plan carries the full list):** `from_parts` round-trip battery (every arm × cap present/absent × error rows); rung-seat `SeatProvenance` byte-identity across the retype; the decide-vs-`Contestant::build` drift pin; the diagnostic-contestant downgrade warning; the version-mismatch warning; `state_at` vs an incremental fold, plus its off-by-one and out-of-range rows; the seven `why` refusal rows; `why` byte-identity; the every-move pin (§2.5); wizard summary echo; HELP_TEXT + guide pair + `guide_sync` (a new command means both guide formats in the same commit, per the standing convention).

**Docs at close:** CLAUDE.md's cli/core count lines, README/guidingpath/map only if a release-tier `#[ignore]` is added (none is planned — nothing here is distributional; the roster stays fifteen).

## 6. What this PR does not do

No new `RecordedEvent` kinds. No recording-default change. No `SEMANTICS_REV` bump, no oracle contact, no preserved-rung edit, no weight or knob change anywhere in core (the two core additions — `state_at`, `from_parts` — plus the echo promotion and the refusal-text repair are additive surface). No roster change. No arena/harness change. `suggest` behavior byte-identical (renderer internals refactored behind its pinned output). The CLI remains incapable of running mcts/atomic-diag seats. Live mode remains bot-free. And **V2 through the CLI ≠ the bar** — this PR is plumbing for the D2 checkpoint's layer 1, nothing more.
