## 1. Why this phase existed, and whether it did its job

Every prior gate proved *self-consistency* — the engine agreeing with itself. The engine-completion final review had found four Critical rules bugs that 15,000 fuzz games structurally could not see, because enumeration and application shared the same wrong belief. This phase built the only tool class aimed at shared-wrong-belief bugs: independent reference implementations, differentially tested.

**It did its job.** The campaign's catches are exactly the predicted class:

- **BuildShophouse slot pinning** (engine, completeness): the generator offered only the first empty slot; the player's real choice among slots with materially different printed rewards was unencodable. Live tracking would desync on a normal strong play; a bot could never learn TR/MR rewards. Invisible to fuzzing by construction — both sides of self-play shared the belief.
- **Chinatown depth cap** (engine, completeness): `CHINATOWN_ENUM_DEPTH = 4` hid legal 5-exchange plays the engine's own validator accepts.
- **BuildTradingHouse overwrite + the raw-arm gap class** (engine, self-defense): the Stage-1 shophouse catch generalized — the Stage-4 census swept all 45 arms and found 14 with ill-formed-payload gaps, including two release-mode money/conservation corruptions.
- **Mining rider omission** (oracle, class 2): the spec transcribed the Chinatown board's printed rates and missed the cross-cutting tech rider — the misreading itself is evidence the interaction is easy to miss at a table.
- **Station teleport precondition** (genuine ambiguity, ruled): surfaced organically in 3 of 60 games by a deliberately-planted probe; ruled by Jeremy (Reading 2) after a correction exchange the decision log preserves verbatim.

## 7. Coverage map

**Now differentially protected (regression-net, runs pre-merge):** legal-move soundness + completeness on engine-reachable states under two drive policies; president-route labels incl. pruning soundness (three-way); final scores + ranking + clockwise tie-break (with a deterministic constructed tie); divergence repro artifacts that cannot rot (fixture guards).

**Protected by pins/invariants (not differential):** end-trigger thresholds & final-round boundary; all 11 VP credit amounts; raw-arm payload defense; board structural integrity; queue resolvability; trigger coherence; record semantics rev + terminal digest.

**Explicitly NOT covered (carry into Phase 3 with eyes open):**
1. **Enumeration on non-engine-reachable states** — the harness compares on states the engine itself produces; a state only a bot's imagination reaches is checked by invariants + raw-arm guards, not differentially.
2. **Banked `base_vp` differential** — amounts are pinned per site and conservation-checked, but no independent implementation re-derives in-game VP accrual end-to-end (a second full oracle; judged disproportionate).
3. **Apply-side reward effects beyond VP/legality** (goods/tokens/cascade contents) — guarded by invariants, conservation, and the choice census, not by an independent re-derivation.
4. **Static data pipeline** (YAML → gen-data → `data.rs`) — trusted per the 2026-07-17 three-way verification program; spot-checks only this phase.
5. **Sequential-vs-budget Chinatown** at the RULES level is ruled (A3 sequential) — but note the differential can only distinguish readings that change move sets on reached states.
6. **`dedup_moves` Debug-key identity** — airtight for every current `Move`-reachable type; a future float/HashMap/manual-`PartialEq` field would silently break the assumption (no mechanical tripwire found proportionate).
7. **Structural board checks re-audit an immutable board every move** (+6s fuzz) — a conscious tamper-at-any-event tradeoff; hoist to once-per-replay if budget tightens.
8. **Chinatown apply validates per-exchange inside its loop** (F2, pre-existing, masked by clone-and-discard) — cosmetic against the validate-all-then-mutate ideal.

## 9. What Phase 3 should still not assume

1. **Do not assume `get_legal_moves` is cheap or bounded** — the factored/lazy action interface remains a MANDATORY pre-search item (handover (b)); the retreat family, not routes, is the volume story (147k-move states are real under non-volunteering play).
2. **Do not search through `apply_move_unchecked` without respecting its contract** — it now self-defends against payload corruption (typed errors, no panics), but Tier-C semantic legality (assistant chains, tech entitlements, affordability) is still the checked boundary's job. A search that fabricates moves gets typed errors, not correctness.
3. **Do not retain training corpora across a semantics bump** — `semantics_rev` exists now; bump it with every behavior-affecting change (A4's resolution, if self-inclusive, would be rev 2). The terminal digest catches silent reinterpretation.
4. **Do not treat uniform-random rollout stats as game facts** — every branching/length baseline is policy-conditional (handover (a): the rollout policy doubles as the fuzzer's family weighting).
5. **Do not assume the oracle is fast** — it is brute force by design (~300ms at pathological states in debug); it is a referee for sweeps, not a rollout component.

## 11. Post-report reviews (addendum, 2026-07-21)

Two external adversarial reviews landed after this report first shipped. Recorded here so the report reflects everything known about the phase's boundary.

**Codex review (PR, disposition 2026-07-20) — fixed at `cdbab5e`.** An adversarial pass raised the record-provenance gap: `GameRecord.semantics_rev` had shipped as a serde-default literal 1, so a stamp-less record silently defaulted to rev 1 and `replay_strict` could not tell a genuinely-old record from a new one. Fixed: `semantics_rev` is now `Option<u32>` and `replay_strict` REJECTS `None` rather than defaulting. Other Codex items (factored/lazy action interface, terminal-digest hardening) were already MANDATORY Phase-3 handover items; see guidingpath's decision log for the full disposition.

**11-lens merge-readiness review (`review-c1.md` + `review-c2.md`, reviewed at `cdbab5e`) — verdict: REQUEST CHANGES.** Eleven review lenses plus direct verification. The review's own summary of the engineering matches this report: the oracle's authored logic is genuinely independent, its 216 rulebook citations are accurate (0 wrong), the card data is clean, the engine's guards/invariants held under ~21M applied moves, and every rule the campaign checked is right. It found **two blockers, both outside the campaign's scope** — pre-existing defects surfaced *by* auditing around the phase, in exactly the place this campaign's tooling was structurally unable to look:

1. **Board topology does not match the printed board.** `board_gen` builds rectangular grids with orthogonal-only adjacency; rulebook p.3 step 2 prints staggered pyramids (each tile touches up to 6 neighbours, not 4). Tile counts match exactly — which is why it survived every gate — but the engine misses ~30% of real edges and invents vertical ones. CONFIRMED against rulebook p.3 by the orchestrator and against the owner's physical edition. Because the layout is a *shared input* to engine and oracle, the differential compared two consumers of the same wrong graph and was structurally blind; the board invariants are non-tautological but fidelity-blind. Blast radius: movement legality, president pass-through fees, Telegram adjacency, canal crossing sets, CLI rendering. The Canal 4-pair geometry ruling was reasoned on the rectangular model and should be re-opened once topology is fixed (it likely resolves to the art's three arrows).
2. **The live-tracking gate cannot be run (order-deck reconciliation gap).** At 2p, 18 of 36 order cards are boxed unobserved; `SetupObservations`/`reconcile_setup` carry no field for the removed pile, so the engine's deck is a seeded guess and `arrange_orders_on_top` hard-requires `order_deck.contains(c)`. Reproduced end-to-end at the first Port take: truthful reveals refused, re-prompting forever (19 of 29 refused at 2p in the sweep). The fix shape exists in-repo — `extract_order_from_deck` searches deck *then* removed pile; the refill path needs the same conservation-by-exchange. This makes CLAUDE.md's former "live gate UNBLOCKED" claim false; it is corrected there and in guidingpath.

**Boundary framing (the review's, adopted here).** Neither blocker is a defect *in* the Phase-2.9 work. Both are cases of a shared input the differential was never able to see — a wrong board graph, and a hidden-information reconciliation gap. As the review puts it: *"That is not a failure of the method; it is the method's boundary."* The campaign did what it claimed within its scope; the boundary is worth recording plainly, which is the point of this addendum.

**Wave plan (this PR and the next).** The review's fixes are sequenced into waves:
- **Wave 1 (this PR):** the mechanical/documentation batch — anti-vacuity assertions, `repro.rs` typed error on unknown phase, doc contradictions and stale counts, the p.16 citations, ruling-list tense, scaffolding removal, and the guide-fidelity fixes.
- **Wave 2 (this PR):** order-deck conservation-by-exchange (the live-gate blocker) plus the desync-guard §6 guide correction that rides with it.
- **Next PR (its own dated mini-plan):** board topology — it spans `board_gen`, movement, Telegram, canal derivation, and `render.rs`, and per the review (and DL line 176's prior deferral) deserves its own spec — bundled with the CLI graphics rework (the staggered-board renderer, area-connectivity legend). The Canal geometry re-opens inside that plan.

## 12. Blocker 1 resolved — board-topology + CLI-graphics PR (addendum, 2026-07-21)

The §11 wave plan sequenced board topology into "the next PR (its own dated mini-plan)." That PR is `board-topology-cli-graphics` (executed 2026-07-21), and **Blocker 1 is RESOLVED**, exactly against the method-boundary framing this report adopted.

**Blocker 1 (board topology) — resolved.** `board_gen` now builds the printed staggered pyramid (rows widest-on-top 4/3/2/1 · 5/4/3/2 · 6/5/4/3; brick-offset adjacency, up to six neighbours; layout-fidelity pins on the row shape and the exact undirected edge counts 18/28/38), replacing the rectangular grids. The Canal re-derives on the corrected geometry: §11 predicted it "likely resolves to the art's three arrows," but the owner instead ruled **any-to-any** on the staggered neighbourhood (1-Yen bank toll; free direct edges govern where tiles also touch; Canal unplaceable/unstoppable) — so the derivation becomes all-neighbour-pairs, simpler than the colinear geometry. `SEMANTICS_REV` bumps 1→2 in the same commit, the first real exercise of the bump contract. This is precisely the shared-input class the report named (§7.1, §11): a wrong board GRAPH consumed by both engine and oracle, so the differential compared two consumers of the same wrong input and was structurally blind. The board invariants were non-tautological but fidelity-blind; the fix restores fidelity, and the layout-fidelity pins make a silent regression to a lattice impossible.

**Finding D1 — a second instance of the same class, also resolved.** The same audit-around-the-phase process that surfaced the two §11 blockers surfaced D1: at 2P the "dummy" pawns on church faith-7 and customs space-4 are, per rulebook p.9's NOTE, taken into account in final scoring to increase competition for the majority bonuses — a rule nobody in the project had modeled. The engine had treated the dummy as an eligibility block and scored majorities over real players only; the oracle read the same track state, so the differential was again blind (shared input, same class as topology). Now both sides model the dummy as a real slot occupant of a sentinel owner competing in the church (6/3) and customs (8/4) majorities — SEMANTICS_REV 2 covers it. The owner's note is worth preserving as evidence the verification campaign educates the owner: *"that's something I've fundamentally misunderstood about the game… I learned something here."*

**Differential re-convergence — the acceptance gate met.** §7 set the standard: "Convergence on the new topology is the acceptance gate." The oracle's test-support boards and the difftest worst-case battery were rebuilt on staggered geometry, and the whole suite re-ran on the corrected graph. Gate evidence: the T5 checkpoint ran all six release gates green on the corrected topology (fuzz 46.06s, census 0.41s, differential 22.54s, routes3 1.51s — no organic route blow-up, own-assistant-subgraph analysis confirmed — scoring 1.78s with D1 convergent on both sides, worst-case 3.11s at bound 519), and the T7 checkpoint re-verified at the frontend-complete tree `2c21709` (the same seven release-tier commands green). The D1 arc specifically flipped a difftest scoring artifact RED→GREEN via rules-only oracle authorship — the engine's scoring was never read — so the convergence is genuine independence, not oracle-follows-engine.

Neither blocker was a defect *in* the Phase-2.9 work; both were shared inputs the differential was never able to see. Resolving them in the follow-up PR is the method working as designed — the boundary was recorded plainly here, and the fixes landed against exactly that boundary.
