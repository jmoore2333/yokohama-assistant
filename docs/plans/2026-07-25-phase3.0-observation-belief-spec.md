## 1. Map amendments this spec carries (evidence-demanded, map §11)

**A. The hidden set is FIVE members, not four.** The map's §2/§5 list (`order_deck` order, `tech_deck` order, `orders_removed` contents, opponents' unfulfilled starting orders) omits **`GameConfig.setup_seed`** (`types/state.rs:22`, inside `GameState.config`). `new_game` is fully deterministic from `(config, rules, seed)` (`game/setup.rs:85-110`, ChaCha8Rng), so the stored seed regenerates the exact deck order, boxed pile, board, and **both dealt cards of every seat** — verified empirically, including recovery of a live-`Unknown` opponent's deal the engine deliberately refuses to store. The seed is write-only in the engine (written `setup.rs:85`, `wizard.rs:440,674`; read by nothing), so the view omits it. The same channel exists in `GameRecord` (`seed` + `choices`, `record.rs:58,63`): **bots never receive records** — a review-enforced rule (§3.5 states what IS structural).

**B. Masking the seed field does NOT fully close the channel — the public board is a seed oracle (residual, executed attack).** `new_game` generates `board_layout` from the same seeded RNG *before* the deck operations (`setup.rs:88-94` then `:97-110`), so the board — which every honest view must carry verbatim — is an injective fingerprint of the seed. Executed against this spec's exact view contract: 5,000/5,000 distinct board fingerprints per player count (play-immutable fields only, so the attack works mid-game); victim seeds recovered by brute force in 0.39–3.78 ms at the repo's conventional small seeds; throughput 389k `new_game`/s ⇒ 0..10⁶ in 2.6 s. Every existing driver uses small sequential seeds (`fuzz_full_games.rs:41` `0..500`; selfplay/difftest `base_seed + i` with documented base 0). **Closure is by seed entropy, not by masking:** see §3.5's seed-hygiene rule and §7-L7. The residual is permanent while `GameRecord` replay requires `(seed, config, choices, events)` determinism — recorded for the map's §8 ledger.

**C. The binding release-gate list grows 7→8** (§4 suite; §9 gate). Additive, within 3.0's authority (map §4's "repo gates unchanged" bars skipping, not adding); the doc obligation covers **four** sites: CLAUDE.md, README (count + table + timing), guidingpath, **and map §4:100 itself** ("the seven release-tier gates").

## 2. Verified fact base (what the design stands on)

Each fact verified by at least one research agent with citations; load-bearing ones independently by two or more; review lenses re-verified ~25 citations (one line-drift found and fixed here: the port refill pop is `cards.rs:230`).

**F1 — Complete field census.** `GameState` 27 fields, `PlayerState` 22, `GameConfig` 6, `BoardLayout` 5 — proven complete by compiling exhaustive destructuring patterns from an external crate (E0027 fires on omission). All fields `pub`; no `#[non_exhaustive]`; derives `Debug, Clone, PartialEq, Eq, Serialize, Deserialize` (no `Hash`, no `Default` on `GameState`/`PlayerState`).

**F2 — The hidden set (per §1-A, five members).** Everything else is PUBLIC at the table, including: money/goods/VP (`00-README.md:85`; public VP track), techs (`01-rules-reference.md:706-708`), completed orders (`:702`), mercenaries — `available`/`used` is a *used marker*, not concealment (`:445`, `:565`; ruling A2 `guidingpath.md:257`), country identity derivable from public inputs (`game/cards.rs:177-201`) — and 5-Power faces, face-up since SEMANTICS_REV 3 (`guidingpath.md:267`). Claimed 5-Power identities are *destroyed* for all observers (`apply_move.rs:922-927` `slot.take()`; count-only `player.rs:218`) — symmetric loss, no mask needed (§7-L6).

**F3 — Opponent hands are all-but-one public.** "When ANY player takes an Order card, ALL players see which specific card was taken" (`01-rules-reference.md:703`). Orders never leave a hand except by public fulfillment (`:464`; sole removal `apply_move.rs:1335`). An opponent's hand = {publicly-witnessed takes} ∪ {≤1 hidden starting order}. **Masking whole hands would destroy legitimate information.**

**F4 — Starting-order storage has FOUR observable cells.**
- *Opponent, SIM `Keep`:* card in **both** `starting_order` and `order_cards_in_hand` (`setup.rs:250-251`); unkept card → `orders_removed` (`:252`). Fulfillment moves the hand copy to public `completed_orders` (`apply_move.rs:1335-1336`) and never clears `starting_order` (write sites crate-wide: `player.rs:244` init, `setup.rs:251`, `state.rs:446`). Post-fulfillment the field leaks nothing new. **Mask predicate: `starting_order.is_some_and(|c| hand.contains(&c))` — "unfulfilled" does real work.**
- *Opponent, LIVE `Unknown`:* card in **neither** site — both dealt cards parked in `orders_removed`, `starting_order = None`, `starting_order_hidden = true` (`setup.rs:254-258`; DL 2026-07-17). The tracked hand under-counts the physical hand by one; the engine's `orders_removed` over-counts the physical box by one per hidden seat. `Unknown` is a tracking fiction, **not** a masking primitive.
- *Own seat, `Keep`:* fully known to self.
- *Own seat, `Unknown`:* representable (the live wizard asks every seat "known or hidden", `wizard.rs:731-753`) — the seat's own hand is unrecorded. The view REFUSES this cell (§3.3).
- *Post-`reveal_starting_order`* the state is byte-identical to the `Keep` shape with the card at the hand **tail** (`state.rs:445` pushes) — a revealed-but-unfulfilled card is therefore re-masked by the predicate above (over-masking: honest direction, LIVE-only, §7-L9). Index 0 is the *setup* position of a kept starting order, not an invariant.

**F5 — Legality is a pure function of the acting seat's legitimate view, FOR KEEP-SHAPED STATES** (every seat's starting order recorded — the shape of all SIM self-play). Zero reads of the five hidden members anywhere on the `get_legal_moves` path (exhaustive audit; `starting_order` is read by *nothing* in engine logic); doubly corroborated by the independent oracle; empirical nulls: 694,553 decision points × hidden-detail variation → 0 legal-list differences; 119,730 deck-partition/permutation resamples → 0 differences. **Scope limit:** on an `Unknown` seat the Port hand-limit gate (`legal_moves.rs:481,493,501`; `actions/cards.rs:55`) reads the under-counted tracked hand, so the engine's list for that seat is headroom-inflated by one; a materialized sample's list is the physically correct strict subset (§7-L8, routed to 3.3). Deck **lengths** are legitimately read (`end_game.rs:28` — length-faithful sampling reproduces the OrderDeckEmpty trigger exactly).

**F6 — Apply consumes hidden state at exactly two sites** — `refill_port` (`game/cards.rs:230`, up to 2 draws) and `refill_lab` (`cards.rs:266`, 1 draw) — so sampled worlds diverge from truth exactly at refills (measured 40/40 2P games; first divergence step min 11 / median 140 / max 886). A refill publicly reveals the drawn card ⇒ **a determinized world is not carry-forward-safe across an observed refill; re-sample or condition after each** (3.3 constraint, part of the sampler contract). `orders_removed` contents are read by no rule. Apply never branches on `starting_order` (120,000 blanked-field steps → 0 divergences).

**F7 — `pending_choices` is fully public** (all seven variants audited; fulfillment reveals the card *before* its rewards queue; queue empty at hand-off, `invariants.rs:179-181`).

**F8 — `check_invariants` (`invariants.rs:21`, pub, ~0.55-1.16 µs release) is necessary but NOT sufficient for sampler validation.** Card clauses are cardinality-only (duplicated ids, out-of-registry ids, deck∩hand overlaps all pass — verified by execution); no zone-exclusivity, no `starting_order` coherence, no mercenary conservation. Conservation clauses are registry-gated (`:71`, `:89`) — a suite under `Rules::empty_for_tests()` tests nothing.

**F9 — Post-setup accounting (measured, all-`Keep`).** Orders deck/removed/ports/hands: 2P **10/18/6/2**, 3P **13/8/12/3**, 4P **16/4/12/4** (Σ=36). Techs: **no tech is ever boxed** (three-term conservation `invariants.rs:88`) — deck 24/24/18, contents fully derivable as `30 − labs − owned`; **only the permutation is unknown**. Seat-relative unseen order pool `U = deck ∪ physical-box ∪ opponents' unfulfilled-starting slots`: **29 (2P) / 23 (3P) / 23 (4P)** at start — largest exactly where the 2P milestone sits. (`unseen_orders`/`tech_deck_remainder` are sets of distinct ids — both registries are keyed by unique id; the only multiset lives at the tech TITLE level and is irrelevant here.)

**F10 — Determinism hazards.** (a) `OrderRegistry`/`TechRegistry` are HashMap-backed; iteration order is process-randomized; **all universe enumeration must sort** (`iter_sorted_by_id`, `cards.rs:47-51,101-105`); `OrderCardId`/`TechCardId` derive **no `Ord`** (`ids.rs:126-129`) — sort via `sort_by_key(|c| c.0)`. This is *untestable in-process* (HashMap seed is fixed per run) — it gets direct assertions (§4-T5), not faith. (b) `Rules::standard()` ~7 µs/call, uncached — take `&Rules`, never construct per sample. (c) Hand position is inert for legality/scoring/replay but permutes the acting seat's contiguous `FulfillOrder` block (`legal_moves.rs:59-63`; 0 set differences in 44,235 probes) — leakage comparisons are by `Move` value; the sampler re-inserts hidden cards **position-exactly** (pinned by fixture, §4-T8b — an acting-seat legal-list equality cannot pin an *opponent's* hand order). (d) `state_digest` hashes hidden fields — the leakage suite needs a **view-level digest**. (e) `BoardLayout.adjacency` neighbor order is insertion-order — clone the layout verbatim, never rebuild.

**F11 — Setup decision surface.** `PendingSetup` carries `deals` for ALL seats plus the fully-seeded state (`setup.rs:51-56`) — an omniscient object at the game's first decision. An honest per-seat Keep decision is handed only `deals[seat]`.

**F12 — No peek effects exist anywhere in Yokohama** (20 tech titles, 6 token faces, 36 order reward slots, 24 sites, every area action audited). Information only ever flows private→public; the hidden set can only shrink.

**F13 — Perfect recall is the honest posture with one gap** — everything a perfect-recall seat knows is recoverable from `GameState` except its **own boxed deal-discard** (anonymized into `orders_removed`). §7-L1/L5.

**F14 — Conventions.** Every sim driver finalizes with `Keep` (the SIM cheat is live exactly where bots train); drivers build `Rules` once; the two-tier gate pattern (per-edit smoke + `#[ignore]` release sweep with documented message + anti-vacuity) is the repo's most consistent convention; `place_setup_dummies` (`setup.rs:197`, pub) is the primitive for hand-built 2P *fixtures* (sampler outputs carry tracks verbatim); `PlayerId::DUMMY` is a stateless sentinel (`ids.rs:76-81`). Debug-tier costs measured: one full 4P uniform game ≈ 0.4–0.9 s debug (~2.3k turns); the trivial agent roughly doubles per-decision cost — per-edit slices must be seed- and step-capped (§4).

## 3. Design

### 3.1 Architecture choice (alternatives considered)

- **(A) Masked `GameState`** (same type, hidden fields canonicalized): rejected — honesty untyped; any code path can silently read a masked field; functional-update syntax silently passes new fields through; `setup_seed` shows how fatal one missed field is.
- **(B) Separate `PlayerView` + belief sampler to full `GameState` (determinization)** — **CHOSEN.** Typed honesty; compile-time drift guard via exhaustive destructure; full engine reuse on sampled worlds (sound by F5); matches the map and `guidingpath.md:119` (determinization suffices).
- **(C) View-native legality/apply reimplementation:** rejected — a second engine (oracle-independence-class burden) for zero benefit given F5.

### 3.2 `PlayerView` (new module `types/view.rs` — pure data)

Seat-relative, seat-generic over N. Derives `Debug, Clone, PartialEq, Eq, Serialize, Deserialize`; **BTreeMap-only** (extends the `semantics.rs:81-93` determinism rationale to the view). `types/view.rs` holds data + registry-free accessors ONLY — no `&Rules` methods, no hashing (layering: `types/` never imports `game/`; §3.3 hosts the helpers).

- `viewer: PlayerId` — never `DUMMY` (typed error).
- `config: ViewConfig` — a NEW type carrying exactly the five public config fields (`player_count`, `player_colors`, `start_player`, `has_port_b`, `has_lab_b`) and **no seed field at all** — the type says "there is no seed here". (Rationale over GameConfig-with-zero: `GameConfig::new` already writes 0 for manual construction, and seed 0 is the repo's documented default base seed, so a zeroed field is indistinguishable from a *real* seed-0 game — `new_game(view.config, rules, 0)` would reconstruct the TRUE game for game #0 of every conventional sweep. Typed absence removes the booby trap.) Derived from `GameConfig` by exhaustive destructure (drift guard intact).
- Cloned verbatim (public, F2): `board_layout` (verbatim clone per F10e), `port_state`, `lab_state`, `church_track`, `customs_track`, `achievements`, `mercenary_supply`, `station_location`, end-game fields (`end_game_triggered`, `trigger_reason`, `final_round`, `trigger_player`), turn machinery (`current_player`, `turn_phase`, `turn_number`, `additional_action_state`, `current_action_power`, `is_mercenary_action`, `mercenary_target_area`, `mercenary_return_phase`, `president_start_area`), `pending_choices`.
- Deck knowledge: `order_deck_len`, `tech_deck_len` (raw lengths — public), and **`orders_removed_len` DERIVED, not raw**: `orders_removed_len = state.orders_removed.len() − #{seats with starting_order_hidden}`. The engine's `Unknown` fiction over-counts the physical box by one per hidden seat (F4); the derived value is the table-true public count (16 setup removals + one discard per seat = 18 at 2P regardless of tracking shape). Registry-free, and stays correct across `reveal_starting_order` (which clears the flag and pulls the card from `orders_removed` in the same call, `state.rs:435-449`). Pinned by a SIM/LIVE same-physical-truth equivalence test (§4-T8c).
- `players: Vec<VisiblePlayer>` — every `PlayerState` field verbatim EXCEPT:
  - `order_cards_in_hand` → `hand: Vec<HandCard>`, `enum HandCard { Known(OrderCardId), HiddenStartingOrder }` (derives `Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize`). Own seat: all `Known`. Opponent `Keep` shape: the unfulfilled starting-order element (F4 predicate, matched by value) becomes `HiddenStartingOrder` **at its true index**; the rest `Known`. Opponent `Unknown` shape: a `HiddenStartingOrder` slot **synthesized at index 0** (the setup position of a kept card; canonical for never-materialized cards), followed by the tracked `Known` takes.
  - `starting_order` → own seat verbatim; opponents `None` always (post-fulfillment identity is already public in `completed_orders`; no rule reads provenance).
  - `starting_order_hidden` → dropped (the `HiddenStartingOrder` slot *is* the signal).

### 3.3 `observe` + helpers (new module `game/observe.rs`)

`pub fn observe(state: &GameState, seat: PlayerId) -> Result<PlayerView, ViewError>`

- Pure; no `&Rules` (masking needs no registry).
- **Mandatory destructure discipline:** exhaustively destructure `GameState`, every `PlayerState`, and `GameConfig` (every field named, no `..`) so any new state field is a compile error until classified. Functional-update syntax is forbidden in this module (module doc states why). Deliberately-dropped bindings are individually annotated.
- `ViewError` (strong typing at the boundary): `DummySeat`, `SeatOutOfRange`, **`ViewerDealUnrecorded`** — the own-seat × `Unknown` cell (F4) is REFUSED: a seat cannot be unknown to itself; such a state is a tracking artifact, not a seat view. Pinned §4-T8d.
- Hosted here (not in `types/`): `impl PlayerView { pub fn unseen_orders(&self, rules: &Rules) -> Vec<OrderCardId>; pub fn tech_deck_remainder(&self, rules: &Rules) -> Vec<TechCardId>; }` — ascending by `.0`, sorted enumeration per F10a (pinned §4-T5). `view_digest(&PlayerView) -> String` lives in `game/semantics.rs` beside `state_digest` (one FNV-1a implementation; `fnv1a_64` stays private to that module; its BTreeMap-determinism doc extends to the view).

### 3.4 `BeliefSampler` (new module `game/belief.rs`)

```rust
pub struct BeliefSampler { /* derived pools + internal ChaCha8Rng */ }
impl BeliefSampler {
    pub fn from_view(view: &PlayerView, rules: &Rules, seed: u64) -> Result<Self, BeliefError>;
    pub fn sample(&mut self) -> GameState;   // deterministic sequence from (view, seed)
}
```

- **v1 contract: conservation + consistency, uniform.** Pools from `unseen_orders` (|U| must reconcile: `|U| == order_deck_len + orders_removed_len + H` where H = hidden slots — with §3.2's derived removed-length this holds for SIM and LIVE shapes identically; violation → `BeliefError::Inconsistent`). Draw a uniform permutation of U: first `order_deck_len` → deck (index order = pop order); next H → the hidden hand slots (seat order, written to **both** `order_cards_in_hand` at the slot's exact index and `starting_order` — always emitting the SIM `Keep` shape); remainder → `orders_removed`, **canonicalized ascending by `.0`** (contents rules-inert; canonical order prevents spuriously distinct samples). Tech deck: uniform permutation of `tech_deck_remainder`. Everything else copied verbatim from the view; the world's `GameConfig` is rebuilt from `ViewConfig` with `setup_seed: 0`, documented: *a sampled world is a fiction — 0 means "not seed-generatable"; never hand a sampled world to `GameRecord`/replay machinery as if it were a seeded game.*
- Construction is by full struct literals (`GameState`/`PlayerState` implement no `Default`), so `belief.rs` inherits the same compile-time drift guard as `observe` — a stated property, and a warning against "cleverly" cloning a true state into the sampler.
- No RNG in public signatures; internal ChaCha8Rng; `&Rules` taken by reference (F10b).
- LIVE-shaped views sample identically to SIM views by construction (the synthesized slot materializes). `BeliefError::HandOverflow` refuses materialization past the hand≤3 bound (unreachable in faithfully-tracked games); `BeliefError::RegistryMismatch` covers unknown ids.
- Perf envelope (informational): sample ≈ clone (0.36-0.68 µs) + two shuffles + writes; no benchmark gate in 3.0 (3.1's business).

### 3.5 `HonestAgent` + trivial agent + honest driver (new module `game/agent.rs`)

```rust
pub trait HonestAgent {
    /// Setup: sees ONLY its own two dealt cards (F11). Return 0 or 1 (driver-validated).
    fn choose_starting_order(&mut self, seat: PlayerId, deal: &[OrderCardId; 2]) -> u8;
    /// Play: sees its seat's view and that seat's legal moves. Returns one of `legal`.
    fn choose_move(&mut self, view: &PlayerView, legal: &[Move], rules: &Rules) -> Move;
}
```

- The name `Policy` is deliberately NOT used (`yokohama_difftest::drive::Policy` exists; map §5-3.2 relocates that enum into core later).
- Handing the true legal list is leak-free **for Keep-shaped states** (F5, scope and all); guarded forever by §4-T4. The driver validates both agent outputs (keep index ≤1; move ∈ legal) with agent-attributed errors.
- **`TrivialHonestAgent`:** owns a seeded RNG; keep → random 0/1; move → construct `BeliefSampler::from_view(view, rules, s)` where **s is drawn from the agent's OWN RNG stream** (never any state-derived value — `state_digest` hashes hidden fields; deriving s from it would correlate the sample with the truth it must be blind to; `view_digest` is the only permissible non-RNG ingredient), draw ONE world, compute `get_legal_moves(&world, rules)`, pick uniformly, **and `apply_move_unchecked` the pick into the sampled world, asserting success** — the one load-bearing sampled-world use (exactly what 3.3's search will do), converting T7 from pure plumbing into a rolled-forward-world check. (Honesty about scope: by F5 the sampled legal list equals the true list, so the sampled world does not influence *which* move is picked — T7 is a plumbing-and-usability proof, not sampler-quality evidence.)
- **`run_honest_game`:** `pub fn run_honest_game(seed: u64, players: u8, rules: &Rules, make_agent: &mut dyn FnMut(PlayerId, u8) -> Box<dyn HonestAgent>) -> Result<HonestGameStats, String>` — the **agent factory is invoked inside the driver** after `new_game`, receiving only `(seat, player_count)`: agents cannot be constructed from `PendingSetup`/records by the caller-of-record, and the factory shape is what 3.2's seat rotation needs anyway. Loop: `new_game` → per-seat `choose_starting_order` fed **only** `pending.deals[seat]` → `finalize_setup` (all `Keep`) → { `observe(state, current)`, **assert `view.viewer == state.current_player`**, `get_legal_moves`, agent picks, membership-check, `apply_move_unchecked`, `check_invariants` } with the incoming-state guard, dead-end error, and `MAX_TURNS` discipline mirrored from `tests/common/mod.rs`.
  - **Loop-drift posture (recorded intent):** this is the deliberate core-side sibling of the tests/common loop (a `tests/` module cannot be imported from `src`); the discipline items held in sync are named (incoming-state guard, per-move invariants, dead-end error, MAX_TURNS=10000), a cross-pin test asserts the shared constants/behaviors, and the carry-forward is recorded that `tests/common` delegates to this loop at 3.2. Construction reuses the exact `new_game`→choices→`finalize_setup` sequence.
  - **Seed-hygiene rule (from §1-B, binding for bot-facing play):** any driver evaluating a `HonestAgent` for real (arena, strength claims) must pass `new_game` a seed drawn uniformly from the full `u64` at experiment creation and RECORD it for reproducibility — small sequential seeds are brute-forceable through the board oracle. Stated in `run_honest_game`'s docs; honesty-suite tests may use small fixed seeds (their agents aren't adversarial); **enforcement lands with 3.2's arena** (recorded handover), not as a 3.0 runtime floor.
- **`HonestGameStats` (defined here so it can't grow a back-channel):** winner/final standings (via `final_result`), turns, moves applied, trigger reason, per-phase branching counters. Agent-validation failures (bad keep index, non-legal move) are **hard errors** — the driver aborts with an agent-attributed message in the repo's `dump_failure` style — so no violation counters ride in the stats (plan-authoring refinement, 2026-07-25). **No terminal `GameState`** — a terminal state carries the whole hidden set + config; callers needing one use a separate, omniscient-labeled function; no trait method will ever hand an agent an outcome carrying hidden state.
- **Leak-canary agent (test-support, `cfg(test)`-gated or `tests/` helper):** an intentionally-cheating `HonestAgent` whose pick folds sampled-world hidden content (deck order, removed contents, materialized hidden cards) into the move index — the detector that makes §4-T2 falsifiable, with a positive control (its pick DOES move when the view legitimately changes).
- **Omniscient posture:** no omniscient trait is built (YAGNI). Standing rule recorded: any future full-state diagnostic policy carries `Omniscient` in its name and never enters honest rankings (3.2's arena is typed over `HonestAgent`). Bridge to 3.2's preserved rungs: `difftest::drive::pick_move` reads only `&[Move]` + RNG, so uniform/retreat-averse wrap trivially as `HonestAgent`s — the carve-out for engine-validation drivers expires cleanly; `TrivialHonestAgent` is the natural seed of the uniform rung (same policy, different RNG stream).
- **Structural-closure scope (honest wording for gate item 3):** the per-decision channel is closed by types (no trait input can name `GameState`/`PendingSetup`); the **construction channel** (an agent value built from a record/seed outside the driver) is closed by the factory shape *within* `run_honest_game` and is otherwise a stated, review-enforced rule; the **coalition channel** (two agents sharing state via `Rc`) is documented, with a test pinning that two seats' views expose disjoint hidden slots (each sees `HiddenStartingOrder` exactly where the other sees `Known`).

## 4. Honesty machinery — the standing test suites

Two-tier per convention (F14): per-edit slice (never ignored, seed- and step-capped — shape: 2P+3P, few seeds, `max_steps` cap à la `per_edit_smoke.rs`; exact numbers fixed in the plan) + `#[ignore]`d release sweep (uncapped 2/3/4P, larger N; the documented-message contract). **Anti-vacuity is per-variant-family:** each family carries its own effectiveness counter (variant ≠ true state) with a per-tier floor — deck-partition variants degenerate exactly where games end (deck empty; 100% OrderDeckEmpty at 4P), swap-variants degenerate once starting orders are fulfilled, so a bare `comparisons > 0` would certify vacuous passes. Conservation tests run under `Rules::standard()` (F8's registry gate).

- **T1 Mask totality (THE leakage detector).** At decision points: derive `view`; construct hidden-detail variants of the true state — deck reshuffle, deck↔removed re-partition, hidden-starting-order↔removed swap, tech permutation, `setup_seed` change — sizes preserved; assert `observe(variant, seat) == view` and `view_digest` equal. Any hidden variation that moves the view is a mask hole. (Own-hand-order permutation is excluded — own order is legitimately visible. The `setup_seed` variant proves *field* masking; the *channel* is closed by §1-B/§3.5 seed hygiene, not by this test.)
- **T2 Decision invariance (canary-armed).** Same variant families; run **the leak-canary agent** (§3.5) with fixed agent seed + fixed per-decision sampler seed on each variant's derived inputs; assert value-identical picks across variants (the canary's pick depends on sampled hidden content, so a sampler or plumbing leak moves it); positive control asserts the canary DOES move under a legitimate view change. `TrivialHonestAgent` runs the same harness as a smoke (structurally cannot fail — F5 makes its inputs variant-invariant; stated honestly). Plumbing pins: in-driver `view.viewer == current_player` assertion; a recording agent asserts the seat it views equals the seat it was constructed for.
- **T3 Sampler determinism + blindness.** Same (view, seed) ⇒ identical sample sequence, across *different* underlying true states with equal views; per-decision seed provenance per §3.5 (agent RNG stream; never state-derived).
