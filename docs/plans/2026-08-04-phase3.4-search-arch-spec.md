**Definitions.** `classify(cell)` ∈ {ABOVE, BELOW, CONTAINS}: a `Bootstrap` interval with `lo > 0.5` (strict) is ABOVE; `hi < 0.5` is BELOW; anything else — including an endpoint landing exactly on 0.5 (lens 1 S1) — is CONTAINS. **Surfaces, evaluated per arm and per cell in this precedence BEFORE classification (lens 1 M3): harness-bug → completion-failure → null-gate.**
- **S1 harness bug:** malformed outcome anywhere → halt, investigate, no adjudication.
- **S2 completion failure:** any game in a cell returning `ArenaError::CapReached` INVALIDATES that cell (never dropped, never silently scored). ## §2 — Design inputs the module is built against (measured; regime qualifiers are part of every constant — L22)

1. **Evaluator leaf, hand-off valuation.** ~40% of a naive per-move UCT's leaf values are read MID-TURN — states V1 was never calibrated on and which S1 by construction never evaluates. The §4 screening compares the two **jointly with the simulation count the shared cap buys each** (lens 1 S5: at a fixed scored cap the modes buy different sims/dec, so the comparison is mechanism × simulation-count, stated as such, with sims/dec reported per config).
2. **Expansion is the cost driver** — 56.8% of a naive sim at 1,024 sims (74.3% → 53.8% across 16 → 4,096; the select column is a prototype artifact — lens 2 S13) — and **Placement roots carry 94% of S1's node budget / 92% of its scored budget from 15.5% of decision points, measured at greedy-play states (critic §6.2 regime A; not re-measured at lookahead-play states — lens 2 M3)**. Allocation, not tree constants, is where the budget goes.
3. **Ordering composite:** eval-order the materialized candidate list at the root and at large-candidate nodes (the ~15–19% share is the organic DECISION-POINT distribution's; the tree-node share is smaller and unmeasured — lens 2 S5); the shipped retreat scheme stands as-is (m samples, `push_unique` dedupe at its measured 10→9.04 distinct rate) — the keyed-index admission rule binds ONLY if §4's screening ever turns a widening arm on, which v2 does not ship (lens 2 S6: v1's blanket "never materialize" contradicted §3.3's "exactly the shipped scheme"); placement ordering operates over the node's materialized Vec, never the family (`get(i)` is O(i)).
4. **Value normalization is explicit** (R5's measured foot-gun: raw-scale UCB makes c inert): leaf values map to [0,1] by a declared monotone squash of the V1 relative margin; the mapping and scale are named in module + provenance; the scale is a screening knob.
5. **L10 discipline**: node owns `(GameState, Vec<Move>, stats)`; `DecisionHandle` scoped temporary; ONE enumeration per node, pinned harness-scoped; forced fast path cached (59.9% of decision points forced; 84.6% of beam-tree nodes — a beam-4 proxy, labelled).
6. **Tie-breaks**: uniform keyed draw at every selecting point — root argmax, UCB selection ties, expansion pick, **and the capped-beam's continuation-order ties (§3.4's new selecting point, row 18 extended to it)** — constant-consumption multiply-shift; the degeneracy pin applies (a constant-valued leaf must still place and terminate).
7. **Keyed streams**: `agent_stream_seed`'s `(world_seed, seat, slot)` keying inherited; per-decision/per-node streams derive by counter keying, never by consumption order tree shape can perturb.

**3.4 The budget meter and cap (the matched-budget instrument, shared).** A `ScoredBudget` meter counts candidate evaluations. **The cap is a TOTAL per-decision cap, root included** (lens 2 M4), with a **mandatory root pass**: every root candidate receives its one-ply score before any deeper work (max realized root size at 2P is 432 < B\*; a root pass alone exceeding the cap increments `budget_starved_decisions` and triggers the fallback). Beyond the root:
- **MCTS-v1**: a simulation is started only while `realized < cap` (lens 1 S2 — no lookahead of a cost it cannot know); a started simulation completes; the overshoot distribution (p50/p90/max) is reported as a validity line.
- **Capped `lookahead-v1`** (`cap=<n>` knob, default OFF ⇒ byte-identical to shipped, golden-pinned): after the mandatory root pass, root candidates receive their beam continuations **in descending one-ply-value order** (ties by keyed draw — the new selecting point), each continuation atomic — started only while `realized < cap`, and a continuation the budget dies inside is discarded whole (deterministic, and it cannot privilege enumeration order — lens 1 M8: v1's in-order loop starved late candidates and, with the empty placement emitted first, re-created ledger row 18's null-placement degeneracy through the budget).
