## Standing notes and carry-forwards

- **S-2 / M5 — AN ESCAPED MUTATION, recorded as one rather than reclassified.** The reviewer removed `Relay::append`'s mutex and `concurrent_appends_never_interleave` still passed: on macOS/APFS a single-`write_all` `O_APPEND` append stayed atomic from 40 KB to 32 MiB. **Adjudication: do NOT delete the mutex** — that atomicity is a property of the filesystem, not of POSIX (NFS does not promise it), and the failure it prevents is silent corruption of the artifact the phase rests on. What was fixed is the CLAIM: the test's comment now pins the outcome it actually demonstrates and says in place that it does not discriminate the lock. Read the test accordingly; do not cite it as evidence the mutex is load-bearing.
- **N-6 — the design's foundation facts are UNVERIFIABLE FROM THE REPO.** Design §1 (the `gamedatas` shape, the notificationHistory endpoint and its token guard, the card-numbering permutation, the takeback in the live log, the absence of `g_gamelogs` in this build) was measured live against table #895608640 on 2026-08-07. A reviewer cannot re-check any of it from the tree, and the table will not stay in that state. Treat those facts as dated observations carrying their table id as provenance — and expect the bridge to hard-error on a shape it does not recognize rather than guess, which is design §6's drift posture.
- **N-7 — honest scope of the committed JS tests.** `bridge/tests/*.js` load the shipped files in a stubbed environment that models only what the code touches. A green run is evidence about this logic; it is NOT proof the extension works in Chrome, where the MAIN/ISOLATED world split, the service-worker lifecycle, and BGA's real transport all become live variables for the first time. The first capture run is what converts that.
- **Two MV3 constraints that drove the architecture** and will bite anyone editing it: a content script's `fetch` is subject to the PAGE's CORS in MV3, so relay delivery must happen in the service worker (which is why `chrome-extension://` really is the origin the relay sees); and `gameui` is a MAIN-world global invisible to an isolated content script, so `main-world.js` (page objects, no `chrome.*`) and `bridge.js` (`chrome.*`, no page objects) must stay separate and talk over `postMessage`.
- **Capture-URL matching is one named constant** in `main-world.js`. If live-follow turns out to need a feed that arrives over BGA's realtime SOCKET rather than fetch/XHR, that is a different mechanism, not another regex — the wrapper cannot see it.
