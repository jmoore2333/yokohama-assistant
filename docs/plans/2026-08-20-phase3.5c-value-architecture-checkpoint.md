**The measured diagnosis (per the owner's decision-1 ruling).** Every strength-relevant failure
exhibit is tagged in §2's taxonomy. The LARGEST REPLICATED class is representation — an input
class — standing beside a smaller own-turn-width class and the unresolved opponent-reply class.
The searches at the exhibit roots were verified healthy (all counters clean — no cap, no bind, no
starvation — which certifies the search ran un-capped and un-starved there, NOT that its horizon
was adequate; §2's classes 2–3 carry the horizon evidence). The clarifying fact: **the dominant
blindness is to PUBLIC state the bot's own `PlayerView` already carries** — the assistant map (a
count today), both players' money and basic goods, order identities/requirements/rewards (the hand
contributes only `HandSize`), the port offers, tech ABILITIES, the opponent's sitting-executable
pending value. Several neighboring fields are COMPRESSED rather than absent — imports, the three
majority mirrors (tech/church/customs), achievement progress, and the current country-set bonus are
all priced — and §4 records
present-vs-compressed-vs-absent per field, because that distinction is what the factorial's
attribution rests on. The hidden set is exactly FIVE members — `GameConfig.setup_seed`, the `order_deck`
order, the `tech_deck` order, the `orders_removed` contents, and opponents' unfulfilled starting
orders — and everything else is public. This is representation debt in the PLAYER stack, not an
information-access problem and not an engine problem (the engine is differentially verified and not
under test here).

**The hypothesis this checkpoint tests (falsifiable, and the milestone's subject):**

> The retained player chassis — a linear top over rules-derived, view-honest features, driven by the
> retained own-turn turn-boundary search — may remain viable **if foundational public-state value is
> represented adequately**. The milestone determines whether the additive leaf can represent it
> without unstable compensation and without embedding planning inside features.

Passing the milestone justifies continuing on this chassis. Failing it produces a CLASSIFIED null
(§5's reading) that ROUTES the next decision — only a witnessed BLOCKING collision or a
post-inspection confirmed incompatibility LOCALIZES a representation failure; a field miss leaves
calibration, coverage, and search live — and the fork ruling is explicit either way, never another
scalar queue.

**What is NOT claimed:** sufficiency is not established — "curable within this architecture" is the
hypothesis under test, never the premise. And the process diagnosis rides with it: the per-scalar
mini-cycle machinery (one/two candidates per cycle, admission gated primarily on held-out fit
improvement) was built for weight-selection inside an adequate feature space; against a

## 3. The architecture contract — layer ownership, ruled before any formula

- **Evaluator (the leaf):** present-state assets, capabilities, and opportunity POTENTIAL —
  arithmetic over the view, no move simulation. Requirement DISTANCE is leaf territory; multi-action
  execution SEQUENCING is not. **A feature that internally simulates moves, routes, or action
  sequences has crossed into search and is out of the leaf.**
- **Own-turn search (retained S1):** converting the mover's own opportunities within the turn.
  Unchanged by this milestone.
- **Opponent-reply depth:** the opponent acting — a separate, later capability decision (the ruled
  re-ask), never smuggled in as a feature.
- **Utility/timing:** `final_result`/official standings own the terminal answer; timing SHAPES
  (deficit-keyed nonlinearity, brake/accelerate policy) are a deferred layer (§6), not this slice.
- **The no-double-counting prohibition:** no event is priced twice across layers. The static
  opponent-pending features (§6 group E) and any future simulated opponent turn must PARTITION the
  opponent's value, never overlap — the V3 margin wash (an aggregate re-pricing five already-priced
  mirrors) is the standing precedent for what double-pricing does to a table.
- **The value-flow LEDGER (the pre-registration operationalizes this contract), with the partition
  fixed HERE so no quantity has two conceptual homes:** one owner per quantity along placement →
  enabled action → produced asset → fulfillment → handoff → recovery. **S owns geometry** —
  reachability, local power, action-capability, and the presence-derived raw OPPORTUNITY quantities
  (production ACCESS and future fee-income/access potential included). **E-resource owns CURRENT
  stocks and their marginal utility** (realized fees land in money and are never separately
  retained). **E-order owns requirement/reward POTENTIAL**, which RETIRES at fulfillment as VP,
  resources, and the current set bonuses take over. **Conditional access-×-need matching belongs to
  S×E** (§6's explicit choice; §5 family 10 tests it either way). Credit neither disappears nor
  persists twice across the chain.

## 5. The feasibility benchmark — frozen inequalities before any fit

**The instrument.** A pre-registered set of rules-derived PAIRED INEQUALITIES over constructed
positions, each pair identical on every feature outside the fact under test WHERE legal states
permit — where collateral movement is unavoidable (a goods change also moves order distance and
achievement progress), the fixture mechanically PRINTS its full feature delta and pre-declares the
collateral — each with a declared margin, all FROZEN before any fitting or corpus read. Families
(the implementation spec fixes the individual pairs and margins):

1. same-count / different-location placement (the e113 shape: enabled action ≻ dead corner);
2. useful vs dead action access (and access that persists vs access already consumed);
3. economics: a fee paid lowers value; a good gained raises it; production access ≻ none;
4. orders: requirement-distance decrease ≻ status quo; executable ≻ distant; reward and flag-set
   increments ordered by MARGINAL set value;
5. two-seat symmetry: relabeling players mirrors the symmetric terms exactly;
6. post-action persistence: value credits the ACHIEVED state — no collapse at the boundary the term
   encourages crossing (the V3 proximity failure class, now a pre-registered control);
7. anti-parking: converting an enabled opportunity ≥ holding it forever;
8. recovery/return-to-hand neutrality corners (the V2 `core > on_board > excess` ordering stands as
   a compatibility constraint unless the spec reopens it with separate evidence);
9. positive controls — g3:93's unique winner (+116 over the runner-up wall) and the shipped table's
   existing correct orderings — are FULL-WEIGHTED-SCORING controls: they run in §7 step 9's
   post-fit gate (with development reads at step 5), never inside the weight-free collision
   conclusion;
10. the CROSSED access-and-need family (MANDATORY regardless of the §6 interaction choice): matched
    vs mismatched S-access × E-need pairs — seafood access WITH vs WITHOUT an executable seafood
    order in hand. Under union-only S+E these are DIAGNOSTIC (they measure exactly the conditional
    value union-only cannot express, making that choice's cost visible); under a chosen S×E
    interaction they are GATES owned by the joint cell.

**Part A — the collision test (weight-free; the primary representation question).** Over the frozen
pair set and the exhibit-class roots: do strategically different states still map to IDENTICAL
complete feature vectors under the proposed set? A collision is unrepairable by ANY weights — it is
the pure representation verdict, before a single weight exists. Epistemic status stated exactly:
e113's standing evidence proves a 36-way EQUAL WEIGHTED SCORE plus one known location-blind
component (`AssistantsOnBoard`); whether the COMPLETE current vectors collide there is itself a
step-4 measurement, never an assumption. **Scope, so equal-in-truth states are never mislabeled:**
a collision BLOCKS only where its equivalence class contains a pre-registered value-DISTINCT pair
(rules-derived or otherwise justified BEFORE the read) — distinct legal moves can be genuinely
equal in value, and no exact adjudication says every e113 successor differs. Unlabelled
organic-root collisions are REPORTED as diagnostics, never treated as architecture failure. Zero
BLOCKING collisions on the frozen pair set is the necessary condition the weights question then
sits on.

**Part B — the bounded compatibility solve.** Does ONE weight table under the SHIPPED table's actual
arithmetic — integer weights, early/late stage interpolation, the production rounding/normalization,
no-saturation bounds — satisfy every pair at its margin, JOINTLY? An idealized unconstrained solve
is nearly tautological (an isolated directional pair is satisfied by any large weight of the right
sign); the test's power is the pairs' SHARED terms pulling against each other — persistence vs
anti-parking on the same term is exactly what killed the V3 proximity candidate — plus the real
arithmetic's bounds. **Margins carry a rules/VP justification or the pair stays direction-only.**
On infeasibility, the MINIMAL CONTRADICTORY SET is inspected before any architecture conclusion — a
bad fixture, an unjustified margin, a formula defect, or a scale incompatibility must be ruled out
first. The pairs double as the red-first adoption fixtures later; solver mechanics are the spec's
concern.

**Evidence weight — necessary, never sufficient.** The benchmark answers "does the feature set
separate what it claims to separate, and can one permitted table serve all the pre-registered
comparisons at once," nothing more. The reading, fixed now:

- **Unrepairable collision, or post-inspection confirmed infeasibility** → the additive
  representation is inadequate FOR THIS SLICE → STOP, owner fork ruling (structured/
  interaction-capable leaf vs other options; neural stays out per map §1.7 unless the owner
  explicitly reopens it).
- **Feasible but no on-policy gain later (§7 steps 6–11)** → the local representation gates passed
  and the gain did not translate on-policy; calibration, coverage, and search REMAIN LIVE
  EXPLANATIONS, recorded as such — the close never claims to localize among them unaided (later
  depth/width work can).
- **Feasible + rooted and post-fit gates hold + the confirmatory field clears CONJUNCTIVELY on the
  JOINT S+E identity (§7 step 11's matrix)** → continue on this chassis; the milestone ships. That
  joint clear IS the milestone's pass — a single-group-only clear is a partial improvement routed
  to an owner decision; it does not discharge the "foundational public-state" claim and does not
  un-confound a depth-negative reading.

## 6. First production scope — two symmetric groups, nothing else

**Group S — spatial/action affordance.** Where assistants sit and what that presence makes
possible: per-area enabled-action value at realizable power, adjacency/movement economy as static
access arithmetic, production ACCESS, and future fee-income/access potential — the presence-derived
opportunity QUANTITIES (§3's partition). Rules-derived (the engine already exports the per-area
reward functions the CLI `areas` view computes from).

**Group E — economic/order opportunity, SYMMETRIC BY CONSTRUCTION.** Money, basic goods, and their
marginal utility; order availability, held-order requirement distance, rewards, prospective import
flow, and flag-set marginals — **computed for BOTH seats over public state.** The two-seat computation is what prices
the exhibited F2 class (sitting-executable opponent value: fulfillable orders, a one-step customs
move). Scope honesty, pre-registered: group E EXPOSES executable opportunities; it does not claim to
price the SEQUENCING/realizability of the opponent's actual next turn — that residual is the depth
re-ask's subject (§2 class 3, §3's partition rule). Internally, E is TWO audited subgroups under one
production group — **E-resource** (money, basic goods, and their marginal utility per §3's ledger)
and **E-order** (offers, held-order requirement distance, rewards, prospective import flow,
flag-set marginals) — each with its own collision, boundary, and rooted non-vacuity gates, so one
strong subgroup cannot carry a broken one into production.

**The S×E interaction choice is part of the architecture hypothesis and is made IN the
pre-registration, explicitly, before any result is read:** either **union-only additive S+E**
(clean factorial attribution; conditional value — an assistant at Fishing Ground is worth more with

interaction terms owned by the JOINT cell** and never by S alone (S internally pricing order need
would falsify the factorial's attribution). This choice is a named owner-interest flag in the
step-1 handover.

**Everything else is instrument-only behind a later explicit decision:** tech ability classes

milestone. **Expanding the production scope mid-cycle requires an owner ruling recorded BEFORE any
result of the expanded scope is read.**
