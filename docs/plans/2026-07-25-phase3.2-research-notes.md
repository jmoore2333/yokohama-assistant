## M1 — drivers and the arena's home (SOUND)

- Every move-picking driver inventoried: the shared fuzz driver `tests/common/mod.rs` (`run_random_game*`, uniform `rng.gen_range` over the materialized list, compiled into BOTH `tests/fuzz_full_games.rs` and `examples/selfplay.rs` via `#[path]`), difftest's `drive_game`/`drive_game_to_end` (ONE `Policy` per game, ~14 call sites), and `game/agent.rs::run_honest_game` — the **only already-per-seat driver** (its `make_agent(seat, players)` factory + `choose_starting_order` routing verified by the critic at source). `piped_dogfood` screen-scrapes the CLI and is not an engine driver.
- What 3.2 must genuinely build: win tabulation (zero arena/win-rate hits in the workspace), paired-seed + rotation loops, CI computation, full-game record emission. `HonestGameStats.result` already carries `final_result`'s `GameResult` (tie-break key `(Reverse(total), clockwise distance from start_player)`; `GameConfig::for_player_count` pins `start_player` = seat 0 permanently).
- **Arena home: core** (`game/arena.rs` + `game/policy.rs` + an example binary), NOT a new crate. Decisive mechanism: the fuzz gate and `selfplay` can only see core's **public API** (the `#[path]` include), which is exactly why difftest's `Policy` is unreachable today; the CLI deps on core alone so `play vs bot` costs nothing; difftest's separate-crate precedent exists to quarantine the oracle dep, which the arena doesn't have.
- **Fuzz cells: ADD weighted, never replace uniform.** Measured (scratch crate replicating the fuzz loop, release, HEAD source, seeds 0..499, 500 games/count; validated by reproducing the recorded 4P A/B and the 46.8s gate within ~1.5%): uniform cell 47.52s, retreat-averse cell 12.54s. Coverage disjointness: retreat-aversion applies **0 of 345,800** nonzero-recovery retreats at 4P (0 of 137,540 at 2P) vs uniform's 19.58%/18.63%, while uniform under-covers area-actions ~4× and builds 13–20× — the two policies cover disjoint halves of the apply surface.
- **The gate clause "ChurchTrackFull > 0%" does not discriminate:** uniform 4P itself measures 1/500 = 0.20% (95% Wilson [0.04%, 1.12%]); retreat-averse 4.40% [2.92%, 6.57%]. The existing `fuzz_500_games_per_player_count` pools `triggers_seen` across player counts and asserts presence only — the 4P collapse is structurally invisible to it.
- Stale doc caught (independently also by E1): the fuzz module doc's "the other three triggers occurred zero times" — at HEAD uniform 2P reaches TradingHousesComplete 3/500 (E1: 6/3000).

## M2 — records, corpus, seeds (ISSUES — both corrected in the spec)

- `GameRecord` has TEN fields; `lockdown` is the working precedent for replay-inert metadata (`#[serde(default, skip_serializing_if)]`, provably ignored by replay). Serde behavior verified **executably**: unknown fields ignored on load, missing defaulted `Option` fields → None, missing required field → hard error. `rebuild_initial_state` calls `new_game(record.config, rules, record.seed)` so `record.seed` always wins; `Session::new_sim` writes `config.setup_seed = 0` while tests write the real seed — `record.seed` is the only trustworthy seed site.
- Map §2's "test records truncate at 40 moves — no corpus exists" CONFIRMED (`RECORDED_GAME_MOVES = 40`), with amendments: a second 120-move truncation in CLI tests; a full-game record is producible via the CLI today; `benches/` absent.
- **Measured record sizes** (out-of-repo scratch, release, HEAD, all 16 records `replay_strict`-verified): 2P uniform mean 187,861 B compact (42.9 B/event), 4P uniform mean 280,956 B, 2P retreat-averse mean 32,194 B, 4P retreat-averse mean 71,488 B; pretty = 2.29× compact.
- Seed hygiene: the rule exists ONLY as prose (`agent.rs` SEED HYGIENE block); the four `base_seed + i` sites wrap silently in release (measured at `u64::MAX-2`) into exactly the small-seed regime `t8f` brute-forces. Paired seat-swapped games are compatible with full-entropy seeds (measured: same seed → identical board and deals); agent RNG must be keyed by **contestant identity, not seat**, or the swap discards the pairing.
- Corpus mechanics (all with in-tree precedent in `difftest/src/artifact.rs`): one file per game, compact JSON, rev-first sharding, zero-padded **hex** seed filenames (decimal SplitMix64 outputs alternate 19/20 digits and don't sort), gitignored corpus + committed generator, and an executable corpus-verification gate (else "emitted records replay strict-clean" is unverified prose).
- **Critic corrections adopted:** (1) the proposed `params: BTreeMap<String, f64>` is compile-blocking — `GameRecord` derives `Eq` and `f64` isn't `Eq`; the spec types params in fixed-point integers instead. (2) `SeedSchedule::from_master(<fixed literal>)` is reproducibility, not entropy — a published compile-time master collapses the seed-oracle search space to the index range; the spec draws the master from OS entropy per run and records it, with fixed masters allowed only as labelled diagnostics.

## M3 — policy ↔ factored surface, honesty, L10 (SOUND)

- **`families()` returns more than one tag at exactly ONE decision-point shape: Movement** (always `[MovementRoutes, MovementRetreat]`) — every other phase is single-family. Verified by code read (critic re-confirmed at `search_actions.rs`) and by E1's executable guard over 133,800 games. "Family weighting" is therefore precisely: a routes-vs-retreat draw at Movement plus within-family weighting elsewhere. Measured share: Movement points are 22.9% of decision points at 4P uniform (E1 `mvpts_frac`), i.e. ~77% of decision points are single-family, confirming M3's derived estimate exactly.
- **L10 cannot be held by discipline once the volume metric exists** — the metric is a second consumer of the same routes count. Hence a first-class enumerate-once handle, plus an executable pin: a `#[cfg(any(test, debug_assertions))]` thread-local DFS counter bumped at `movement::enumerate_president_routes` AND `route_enum::walk_routes_costed`'s non-delegating arm (one DFS counts once regardless of provenance; an accidental `get_legal_moves` in the policy is caught too), asserted ==1 at Movement points / ==0 elsewhere, mutation-proven. This requires a third sanctioned `movement.rs` edit (cfg-gated, compiled out of release binaries) — named in the spec with the zero-semantic-change evidence restated.
- **The honest-driver trap:** `run_honest_game` materializes `get_legal_moves` at every decision and validates with `legal.contains` — an arena built on it re-pays the exhaustive ceiling 3.1 exists to remove, for exactly the consumer 3.1 was built for. The arena driver goes families-first over a `BeliefSampler`-determinized world with `move_legality::is_move_legal` (design A) validating the chosen move; leak-freedom is the T4 view-measurability result composed with the union+order equivalence. The fuzzer runs the identical policy function over the raw true state — honesty is a property of **which state you hand the policy**, enforced at the agent boundary.
- Parked PR #8 items: `FamilySize` adopt (the metric is a real consumer of exact-vs-upper); `retreat_move` over-count `debug_assert` adopt (the weighted draw calls the constructor directly); `from_hand` — M3's fork resolved by E1's evidence (none of 28 screened shapes reads it) → **remove**.
- Honesty-thread additions: extend the honesty sweep's T4 block to the factored surface (covers `placement_upper_len`, currently uncovered); two non-vacuous leakage tests (seed-provenance canary; weight-vector invariance under hidden variation); re-run the equivalence sweep under the weighted pick function (L11 applied to the equivalence gate's visited-state distribution).

## M4 — CLI play-vs-bot (SOUND)

- Small, well-seamed: the bot's move flows through `Session::apply`'s existing legality gate and is recorded as an ordinary event, so replay is exact for free; `describe_move` is wildcard-free; `observe`/`BeliefSampler`/`HonestAgent` are re-exported at the crate root. **Live-mode bots are structurally impossible** (`ViewError::ViewerDealUnrecorded`; reveal choreography would deadlock) — sim-only is a fact, not a preference.
- The four real design decisions: (a) the bot pump needs BOTH call sites (`main.rs` before the opening prompt — or a bot on the start seat never moves — and the apply success arm); (b) undo must unwind the whole trailing bot run + the human's last move (index-derived bot seeding otherwise makes single-pop a deterministic no-op — traced and confirmed by the critic); (c) bot seats ride the SAME per-seat provenance field as arena records (one controller concept, `Human` included); (d) a bot seat's hand must be hidden — `privacy` defaults OFF in sim and the panel currently prints every seat's hand including the bot's unfulfilled starting order.
- Measured (scratch crate, path dep at 1c84cec, K=1 world): a full honest bot decision (observe → from_view → sample → world legal list → pick) costs mean 4.42 µs at 2P / 7.22 µs at 4P release, 67.4/96.6 µs DEBUG (the profile testers run) — latency a non-issue. One bot turn = 4.4–7.2 applied moves (max observed 13–19). **Critic caveat adopted:** this times the materializing path, not the recommended families-first path; the conclusion survives a fortiori (the factored path is strictly cheaper) but the figure is labelled accordingly.
- 2P uniform-random games run a mean 1244 turns — `play vs bot` **hard-depends on the family-weighted policy** to be playable at all.

## E1 — weighting-shape screening (SOUND; the decisive experiment)

Harness: `<scratchpad>/e1-weighting/` (out-of-repo crate, path dep on core, release; raw-`GameState` fuzzer-shape driver — sanctioned for shape screening and stated on every figure; policies consume ONLY the factored surface — `get_legal_moves` appears nowhere but a comment; L10 discipline held: ONE `iter_family(MovementRoutes)` collect per Movement decision point serving both metric and draw). 28 shapes × 2/3/4P screened at N=1000/cell (master A), seven finalists re-run on a **held-out** seed set (master B, N=2000/cell); ~143k games / 256M+ decision points. Fidelity: the uniform bracket reproduces all four published reference points (2106.5 vs recorded 2161.6 turns 4P, 9207.5 vs 9447.7 moves, RA 271.7 vs 276.8 turns, RA VP 80.91 vs 82.5); the RetreatAverse reimplementation is stream-faithful to difftest's classifier.

1. **The design space collapses to one scalar at the family level.** families-flat IS p=0.5; a weight table with retreat weight w IS p = w/(1+w). A per-family weight map is machinery for a problem the engine does not have.
2. **The family knob alone does not clear the 4P gate:** sweeping p over [0.01, 0.9] lifts 4P ChurchTrackFull from uniform's 0.27% only to ~1.1–2.0%, statistically flat below p≈0.33 — while retreat-averse at a comparable retreat RATE reaches 5.60%. **The real lever is the within-family recovery amount**: 0.7% → 1.7% → 2.2% → 3.9% → 5.0% as recovery goes max-of-2 → uniform → min-of-3 → min-of-5 → all-zero, at fixed p. On-board assistant density is simultaneously what makes play score-productive and what inflates the retreat product — one variable, two symptoms.
3. **Recommended shape `low5_0.1667` (two knobs):** P(retreat family | Movement) = p = 1/6, and each area's recovery count = min of k=5 iid U{0..=count} draws (full support — every recovery vector including maximal keeps positive probability, unlike retreat-averse which has ZERO coverage of the family's interior). Held-out 4P: ChurchTrackFull 3.7% (74/2000, Wilson [2.96, 4.62]) vs uniform 0.35% [0.17, 0.72] — disjoint intervals; turns 265.2 vs 2106.5 (7.9×); winner VP −2.19 ± 0.85 vs the RA reference (2P −1.20 ± 1.42, indistinguishable); 2P 99.4 turns, all five end triggers reached organically (the only shape that did). Fallback `low5_0.05`: smallest VP gap (−1.39 ± 0.86), ChurchTrackFull 2.90%, lighter tail. **Narrowed box: p ∈ [0.05, 0.20], k ∈ [3, 5]** — everything inside clears the acceptance shape; corners differ by less than the CIs.
4. **The six-figure tail was universal among collapse-fixing shapes in the screen — and free.** Even flat p=0.5 hit 165,903 at N=2000; the recommended shape observed max 186,634 held-out (largest anywhere in the sweep: 331,828 = 75% of the known reachable 442,384 — shape `low3_p=0.3333`, OUTSIDE the shipped box, 4P n=1000, screening master `6435445196422466881`), at ≥10^5 frequency 21.7 per million decision points — while costing 2.48 µs/decision, 3.05× CHEAPER than uniform's 7.58 µs (held-out N=2000/cell; raw-state fuzzer-shape driver, no validation, no invariants — clean-eyes lenses re-derived these from `screen_confirm.tsv`, correcting E1's reported 2.45 µs/3.1×/27×, the last a mismatched-N ratio), because the factored surface makes the tail a counting observation, not a cost. A screened observation with a mechanism, not an impossibility. Hence the spec restates the tail criterion as recorded-tails + executable cost-bound.
5. **L11 data (route labels under candidate policies), initially unreported, surfaced by the critic:** organic route-label MAX at 4P n=2000/cell — 71 (uniform) / 205 (`low5_0.1667`) / 256 (`low3_0.1667`) / 285 (`low5_0.05`), against L11's recorded organic max 38 (uniform, 36 games). The shipped policy moves the organic route-label maximum ~5.4×, into the same order as the release gates' dense adversarial cells; the mean barely moves (rt_mean 4.25 vs 3).
6. Caveats carried: selection-vs-held-out separation (the spec gates on held-out numbers only); per-decision volume metric's Placement term is an upper bound (biases AGAINST the recommendation — safe direction); winner VP confounds efficiency with game length and flips sign at 2P (only the 4P paired delta is used); rare-trigger counts are existence observations, never rates; wall-clock from the quiet pass only; pairing is on setup only.

## E2 — arena variance + CI sizing (SOUND; methodologically strongest)

Harness: `<scratchpad>/e2-ci/` (out-of-repo crate, path dep on core + DEV-dep on difftest for faithfulness pins; per-seat-policy raw-state driver; ~811k games, ~12 min re-run on 10 cores; 11 faithfulness pins green incl. `a_single_stream_game_reproduces_the_difftest_driver_exactly` — the critic re-ran them and re-derived every sizing cell by hand).

1. **The mandated bracket pair is degenerate:** RetreatAverse beat Uniform **4000/4000 games** at 2P (2000 paired+swapped pairs; mean totals 127.4 vs 9.6 VP) and **400/400 games across 100 rotation blocks** at 4P (lens-corrected denominator) — θ̂=1.000, zero per-pair variance, so t/bootstrap intervals **collapse to zero width** (a silently dishonest "±0.000"). The two preserved bracketing rungs are non-comparable; the arena's first real ranking exercise must be against something in between, and the gate must refuse zero-width intervals.
2. **Seed pairing buys ~0–2.5% of variance at 2P (ρ ∈ [−0.024, +0.005]); seat swapping is the whole point** (unswapped arrangement gap up to 3.6pp). At 4P the sign flips: sharing one seed across a rotation block gave ρ=+0.051 and COST 13% variance. Keep seed-sharing as bookkeeping and bias-removal, never claim it as variance reduction.
3. **CRN keying trap (found by accident, highest-value bug in the packet):** keying move streams by seat alone makes a same-policy null cell EXACTLY degenerate (ρ=−1.0000, θ̂ identically 0.500, SE 0.000) — an arena that reads "perfectly calibrated" while measuring nothing. Key move streams by (seed, seat, contestant-slot); keep setup streams keyed by (seed, seat) so paired arrangements share a bit-identical start (pinned).
4. **Seat-0 advantage at 2P is entirely the clockwise tie-break:** pooled 20,000 seat-balanced games — seat 0 wins 0.5070 (SE 0.0035); non-tied games 0.5007; exact ties 1.26%, every one to seat 0. Re-measure the tie rate per rung; it scales the bias one-for-one.
5. **All four CI methods agree in the normal regime** (widths within 3% at N=2000; coverage 94.5–97.0% at N=400 over replicates). Primary: percentile bootstrap over the design unit (pair at 2P, block at 3–4P), B=10,000, resampling seed recorded; unit-level t as cheap default; Wilson-on-pooled-games printed as cross-check but NEVER primary at 3–4P (ignores clustering; 4P ρ=+0.051 → ~93.2% true coverage).
6. **Sizing from a pre-specified minimum meaningful edge, never a pilot point estimate** (measured hazard: a 0.28pp-high pilot θ cost 20 points of power — 80% predicted, 58–60% measured). Defaults from measured variance (Var_pair ≈ 0.1225 at θ=0.5): rung-vs-rung promotion at MME 0.60 → 94 pairs (round to 200 pairs / 400 games, CI half-width ≈0.05, <2s single-threaded); milestone-bar precision target h=0.02 → 1,189 pairs/rung. **Peeking measured: 8 naive looks → 19.0% type-I** (Bonferroni z=2.7344 → 5.2%); fixed N by default, alpha-spending if early stopping is ever wanted.
7. Null cells: θ̂ = 0.4990 / 0.4938 at 2000 pairs — the "instrument reads zero" standing self-test (also catches the CRN trap: SE exactly 0 is the signature).
8. VP-margin statistic: 1.4–2.1× fewer pairs for equal power — adopt for screening/triage; win rate stays the gate statistic ("plays to win").

## Archaeology — the guidingpath:173 probe row (critic hard stop)

The :173 row's figures ("4p Movement option counts median 17,287 / p90 77,770 / max 147,467; 2p max 10,376" — non-volunteering policy, release, 40 games/cell, 2026-07-20) do not reproduce under ANY 2026-07-25 harness at SEMANTICS_REV 5: E1 all-decision-points median 1 / p90 171; Movement-point retreat-family median 128 / p90 576; per-game maxima median 4,808 / p90 41,484 (retreat-averse 4P, n=2000) — only the maxima are in-family (165,901 vs 147,467). **Probe result (executed this round; harness `<scratchpad>/probe_src/probe.rs` `include!`d into two crates — one path-dep on a detached worktree at `aa198dc` (the last pre-topology master commit, PR #3 merge, 2026-07-20; `BOARD_DERIVATION_VERSION = 1`, `SEMANTICS_REV = 1`, rectangular board verified in its `board_gen.rs` module doc) and one on today's core — so the harness is held EXACTLY constant; zero API adaptation needed; release; era-faithful setup (per-game ChaCha8 stream, `Keep(gen_range(0..2))`, cap 10,000); seeds 0..40 at the row's N, deepened to 0..1000; three policy readings since "not volunteering retreats" is ambiguous (P1 exclude nonzero-recovery returns only; P2 exclude the whole return family; P3 strict-with-forced-all-zero); worktree removed and pruned after):**

- **The pre-topology hypothesis is REFUTED.** At the same denominator/policy/seeds the two revs agree within sampling noise on every reading (4P P1 n=1000 per-game maxima: rev1 6,914/46,090/165,902 vs today 4,618/46,082/147,468). The retreat product is governed by area count and assistant spread — identical 18 areas / 17 non-Canal at both board models.
- **The row's two MAXIMA reproduce, at BOTH revs:** 4P 147,476 observed (rev1 P2, n=40) vs 147,467 recorded — 0.006% apart, and the retreat-family component matches EXACTLY at 147,456 (the row's "147,456 of 147,467"); 2P 10,376 occurs exactly (it is rev1 2P P2's p99 of per-game maxima at n=1000).
